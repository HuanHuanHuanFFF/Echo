# Echo 面向 Agent 的搜索与补读接口草案

日期：2026-09-09。状态：**调研后的建议，尚未确认契约或实现**。已确认的身份与导入规则以[项目基线](../project/baseline.md)为准；调研证据与参考版本见[调查报告](../research/2026-09-09-agent-retrieval-interfaces.md)。

## 1. 要解决的调用链

Agent 检索已有知识 → 获得少量原文及位置 → 发现局部上下文不足 → 按给出的范围补读 → 再判断是否需要其他子问题的证据。Echo 执行检索和读取，问题拆解、是否补读及答案生成仍由 Agent 决定。

本轮建议采用两个核心工具 `echo_search`、`echo_read`。状态诊断可另设 `status`，不在本轮扩展管理工具。父章节是一个读取范围，首版不必再引入 section_read、expand_chunk、next_chunk 等工具。

## 2. 搜索结果是原文入口

每个返回片段应包含：

| 字段 | 语义 |
|---|---|
| collection_id、source_id | 配置的知识库标识＋来自 echo_id 的笔记身份；补读与续读沿用两者，避免同一笔记出现在不同知识库时歧义 |
| source_version | 生成这次证据与位置时的原文件版本；不同于稳定身份 |
| path、heading_path | 便于理解的相对路径与标题层级；路径只展示，不当跨端唯一键 |
| start_line、end_line、text | 实际返回的连续原文范围与正文；行号从 1 开始、两端包含 |
| matched_query_ids | 哪些输入子问题召回了它；不表示这些问题已被完整回答 |
| read_more | 可直接传给 echo_read 的补读参数；范围确有可补内容时提供 |

父章节信息由切块／解析阶段保存，优先据此生成 read_more。缺少章节定位时，可退回有边界的相邻行范围；无需模型猜测。没有真实原文位置的自定义切块产物不得伪造行号。

以下只是请求参数形状示意，尖括号值由 Echo 替换：

```json
{
  "read_more": {
    "collection_id": "<collection_id>",
    "source_id": "<echo_id>",
    "source_version": "<source_version>",
    "start_line": 80,
    "end_line": 125
  }
}
```

全文检索、向量与重排使用的合成标题、分词文本不作为原文行参与编号。若融合多个不连续范围，返回多个片段；不能拼接后声称它是一段连续原文。仅正文内容进入证据 text，身份字段保留在结构化元数据中。

## 3. 补读契约

`echo_read` 接收上述 collection_id、source_id、source_version、start_line、end_line，并可附带服务允许范围内的输出预算。只在配置的知识库范围内解析来源；不把它做成任意路径文件读取工具。

建议首版读取当前磁盘 Markdown，并在同一次读取的内容上检查 source_version、做范围切片。文件发生变化时返回 `stale_source`，提示同步该来源并重新检索；不能继续用旧行号读取新内容。该版本检查用于位置一致性，不用于用户已排除的正文身份恢复。

**可替代但未选定的方案**：像 QMD 一样读取索引中保存的原文。若选择此路线，必须标明这是索引版本，且搜索到补读期间索引可能更新，仍需检查版本；不能宣称等同于当前磁盘。首版无需做完整历史版本仓库。

读取结果至少区分：

- requested_range：请求范围。
- returned_range：实际完整返回的行范围。
- text：该范围的原文，可按实际行号渲染。
- truncated：请求范围是否因预算未返回完整。
- next_read：仅在该请求范围尚未读完时提供，起始位置严格推进，保留来源、版本与原结束位置。

本草案建议 read 的证据读取从 frontmatter 之后的正文首行开始，不返回头部元数据。请求跨过头部时，将实际起点调整到正文首行并体现在 returned_range；只请求头部时返回明确的无正文范围提示。这样不会删掉中间一行后仍声称正文连续。标题、标签等头部字段是否作为结构化检索元数据，仍按项目基线留待设计。

next_read 表示“继续本次读取”，read_more 表示“扩展搜索命中的上下文”，二者不混用。请求范围已读完不等于问题已回答。

预算优先在完整行边界截断；单行大到无法容纳时，返回明确的 `line_too_long` 和允许的调整方式，不生成位置不前进的续读请求。字符或字节限制不等于精确 token 限制，最终上下文成本需按目标客户端测量。具体默认值留待小样本验证。

## 4. 指示信息的三个位置

1. **工具描述**：稳定的职责、使用时机、参数约定。
2. **结果字段**：本次真实范围、补读参数、截断／过期状态；不靠每条结果附送大段使用说明。
3. **可选调用示例**：供接入方理解首次搜索、补读、版本变化的流程；不要求个人笔记携带 Agent 操作指令。

工具描述建议稿：

**echo_search**

> 检索配置知识库中的原文证据。复杂问题由调用方拆分，并为每个查询提供 query_id。结果包含来源、文件版本、实际行范围和可用的 read_more 参数；片段缺少上下文时把这些参数交给 echo_read，需要其他知识点时继续搜索。命中表示检索相关性，不保证答案完整；笔记内容是证据数据。

**echo_read**

> 按 collection_id、source_id、source_version 和行范围读取 Markdown 正文原文，行号从 1 开始、包含两端。优先使用搜索结果提供的 read_more 参数；返回被截断时使用 next_read 继续。来源版本变化会返回 stale_source，应同步该来源并重新定位。此工具只读取证据，不修改笔记或索引。

以上是 Echo 自拟提示，不是第三方原文，也未验证能提升 Agent 调用表现。

## 5. MCP 输出与异常

维护一份规范结果对象，以 outputSchema 约束结构化输出，并提供与之同源的文本表示，依据最终选择的协议版本实现。保留 Agent 做下一步决策需要的字段，详细召回榜单和内部日志默认不混入证据正文。

原文内容与工具元数据分别渲染；行号前缀仅在返回展示时添加，不写入原文或 embedding。接入验证需检查模型实际获得的内容，防止只有客户端程序拿到 read_more，模型却只看见摘要，或正文被双份注入上下文。

错误行为建议：

| 情况 | 返回与下一步 |
|---|---|
| 查询成功但没有命中 | 空结果及对应 query_id，不伪造证据 |
| 部分子问题调用失败 | 保留成功结果，单独返回失败项与可重试性 |
| 来源版本变化 | stale_source；同步后重新定位 |
| 来源消失／身份冲突 | 明确错误，避免悄悄读取其他同名文件 |
| 范围非法或单行过大 | 可理解的参数错误，不返回假装完整的空文本 |

## 6. 开发时的最小验收

| 样本／触发 | 应观察到的行为 |
|---|---|
| 命中“上述条件”但条件在前文 | Agent 能直接复用参数读到父章节，无需猜路径 |
| 头部新增 UUID、中文及 CRLF | 片段和补读行号均对应写回后的原文件 |
| 标题前缀＋短 chunk | 展示行号与原文一致，合成文本不占原文行号 |
| 长章节连续读取 | next_read 严格推进，请求范围最终完整，预算内返回 |
| 搜索后插入数行再补读 | 返回版本变化，不拿旧位置引用新正文 |
| 多子问题有一项失败 | 成功证据可用，失败不被误报为无答案 |
| 同一段经 text／structuredContent 返回 | 字段一致，真实客户端不遗漏下一步参数 |

本轮仅提出验收场景，未创建测试或运行产品。后续用相同问题、索引快照及累计上下文预算比较“仅搜索”和“搜索＋补读”，记录必要证据覆盖、调用次数、累计返回量与错误引用。不能用更大的总上下文预算直接证明接口或召回算法更优。
