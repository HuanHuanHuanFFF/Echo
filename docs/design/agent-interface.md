# Echo 面向 Agent 的搜索与原文定位接口草案

日期：2026-09-15。状态：**范围决定以[项目基线](../project/baseline.md)为准，具体字段与协议仍为草案；尚未实现。**

## 1. 当前调用链与工具边界

Agent 调用 Echo 搜索 → 获得证据片段、文件路径和原文范围 → 使用宿主已有的文件工具补读 → 决定继续查询或生成答案。

本轮确认的本地读取、同步前提和引用链范围见[项目基线 §1.3](../project/baseline.md#13-本地读取与同步边界2026-09-15-已确认尚未实现)。此前本文件中的 echo_read、read_more 调用参数、next_read 续读和 stale_source 读取协议退出首版设计；不再作为实现要求。

核心搜索工具暂名 `echo_search`；是否增加独立 `status` 工具仍待定。搜索数量参数的已确认语义见[项目基线 §1.2](../project/baseline.md#12-搜索返回数量2026-09-15-已确认尚未实现)。

## 2. 搜索结果中的定位元数据

以下为字段建议，最终命名、必填项和路径表达仍待确定：

| 字段 | 用途 |
|---|---|
| collection_id、source_id | 知识库标识与来自 echo_id 的稳定笔记身份 |
| path | Agent 能用于本地读取的文件路径；采用绝对路径还是根目录加相对路径待定 |
| heading_path | 标题层级，帮助理解命中所在章节 |
| start_line、end_line、text | 实际连续原文范围及正文；行号从 1 开始，两端包含 |
| matched_query_ids | 召回该片段的子问题标识，不表示已完整回答 |
| section_start_line、section_end_line | 可选章节范围，由解析或切块阶段提供，帮助宿主工具补读 |
| source_version | 可选索引版本信息，用于诊断；不是宿主文件工具的强制校验协议 |

原文位置对应完成 UUID 写回后的完整文件，包含 frontmatter 所占行数。过滤 echo_id、添加检索标题或分词不能改变原文坐标。搜索证据正文与用于召回的合成文本分别保存。

自定义切块也需要可追溯位置。多个不连续范围应分别表示，不能拼接后伪称一个连续范围；具体产物格式待切块接口设计确定。没有章节边界时可只返回片段范围。

## 3. Agent 指示信息与输出

工具描述应说明：Echo 返回证据，Agent 负责拆问题、使用已有文件工具补读和生成答案。补读提示使用路径与行范围等工具无关的元数据，不绑定某个宿主的文件工具参数。

结果应保留 Agent 下一步需要的定位与查询归属，详细排名轨迹默认作为诊断信息。原文属于证据数据；搜索命中不代表答案充分，也不保证不同来源包含不同知识。

建议维护同一份规范结果对象，再按选定 MCP 协议生成结构化和文本输出。接入时验证 Agent 实际能看到路径与范围，避免字段仅对客户端程序可见，或正文被重复注入上下文。

错误与不足的建议处理：

| 情况 | 处理方向 |
|---|---|
| 查询成功但没有命中 | 返回空结果及对应查询状态 |
| 部分子问题失败 | 保留成功结果，区分失败与无命中 |
| 返回数量不足 | 遵守项目基线的硬上限，返回实际片段；诊断字段待定 |
| 同步遇到身份冲突或来源处理失败 | 明确报告同步未成功，不伪称索引已刷新；具体机制待定 |

宿主文件工具的分页、截断、读取权限及异常由宿主处理。Echo 不为其定义统一读取响应。

## 4. 开发时的最小验收

| 样本／触发 | 应观察到的行为 |
|---|---|
| 命中片段缺少前文 | Agent 能用返回的路径与范围，通过已有文件工具补读 |
| UUID 头部、中文及 CRLF | 搜索位置对应同步后的完整文件 |
| 默认／自定义 chunker 附加标题 | 检索文本可以变化，引用原文和坐标仍准确 |
| 笔记改名或修改后成功同步 | 同一 UUID 对应的新路径、内容及位置正确刷新 |
| 单篇上限导致不足 topk | 不填空项，不突破单篇上限 |
| 多子问题中有一项失败 | 成功证据可用，失败不冒充无答案 |
| text／structuredContent 输出 | 定位和内容一致，Agent 能获得后续操作所需字段 |

尚未创建或执行这些测试。比较“仅片段”与“搜索后由宿主补读”时，应计入累计上下文预算、读取次数与证据覆盖。
