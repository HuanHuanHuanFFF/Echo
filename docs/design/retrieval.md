# Echo 检索设计草案

更新日期：2026-09-15。状态：**检索实现仍为草案；已确认的职责、身份、返回数量与定制规则以项目基线为准，均尚未实现。** 项目已确认决定见[项目基线](../project/baseline.md)，改进动机与样本限制见[评测分析](../evals/2026-09-05-chroma-baseline.md)。

## 1. 设计问题

现有小样本的主要缺口是复杂问题证据不完整，以及同篇／跨层内容占用返回名额。目标是保留切块定位能力，改进候选覆盖与结果组织。BM25＋向量＋RRF 是检索目标，但各步骤的实际增益仍需对照验证。

## 2. MCP 工具草案

搜索结果如何提供路径与原文范围，供 Agent 使用宿主文件工具补读，集中讨论于[Agent 接口草案](agent-interface.md)；外部依据见[2026-09-09 调研](../research/2026-09-09-agent-retrieval-interfaces.md)。以下只保留工具职责，不在两处重复维护详细契约。

| 暂名 | 职责 | 待定契约 |
|---|---|---|
| `search` | 单问题或有限子问题的混合检索，返回可追溯证据 | query/query_id、范围、候选预算、返回数量参数的默认值与取值范围、返回 token、重排开关 |
| `status` | 显示索引与模型状态、更新时间及未完成工作 | 诊断字段、部分失败与降级提示 |

已确认：Echo 返回原文片段及定位，外层 Agent 负责最终回答。显式索引同步走管理命令仍是建议；同步触发方式及是否开放写入 MCP 工具另行确定。

## 3. 两路召回和子问题

建议流程：

```text
原问题＋可选子问题
  → 每个检索问题分别进行 BM25 与向量召回
  → 问题内 RRF 融合
  → 文档分组与可选重排（相对顺序需实验确定）
  → 跨问题合并，保留问题与证据的对应关系
  → 组内选片段、合并重叠内容、按总 token 预算打包
  → 返回来源与证据
  → Agent 使用已有文件工具按需补读并综合回答
```

BM25 负责词项匹配，向量负责语义相近，RRF 融合不同榜单的排名，rerank 在已有候选内精排。RRF 不自动保证子问题覆盖，rerank 不能找回候选池中根本没有的证据。保留原始分数、排名和阶段信息；不直接混加 BM25 分数与向量距离，不把 RRF 分数当答案置信度。

区分：
- 查询扩展：同一意图的不同表达。
- 子问题拆解：一个问题需要多个方面的证据。
- 依赖式多跳：后一次查询使用前一次检索到的新信息。

建议接口明确区分“一个 query_id 的不同表达”和“多个独立 query_id”。前者可在问题内融合；后者保留各自候选、命中及失败状态，再按总预算合并证据。批量调用本身不意味着跨问题 RRF。源码对照与原因见[三项目补充调研 §3](../research/2026-09-15-retrieval-reference-comparison.md#3-qmd学习编排过程不直接继承排名策略)。

已确认由调用方 Agent 拆子问题，Echo 不拆解，只执行检索和组织证据。原问题是否额外召回、跨问题权重、失败回退和每个问题的配额仍未定。没有证据时显示缺口，不能为满足配额塞入无关片段。

## 4. 文档分组检索：当前优先实验

用户提出过“按文档聚合，只算最相关的几个片段”。对应 grouped retrieval / result collapsing。它需要分别定义**文档排名**和**组内片段选择**。

### 文档排名

1. 在足够大的候选池上按 `note_id` 分组。
2. 起点方案：以每组最高分片段代表文档相关性。使用同一阶段、方向统一的相关性分数；对距离则取最小值或明确转换。
3. 文档只竞争一个组名额，避免同一篇的多个片段逐个占满外层文档组预算；该内部预算不同于已确认的返回片段数参数 `topk`。

不直接对所有片段分数求和，否则长文档或切得更碎的文档可能因数量占优。最相关几个片段的均值、加权或子问题覆盖分数可以后续比较，不能当成已经确定的“综合相关性”公式。最高分也不能完全消除长度偏差。

### 组内片段选择

返回数量参数的已确认规则见[项目基线 §1.2](../project/baseline.md#12-搜索返回数量2026-09-15-已确认尚未实现)。选中文档后保留最相关的少量片段；每篇 2～3 个只是默认值的实验起点，文档组预算、参数默认值和 token 预算尚未确定。保留 Mechanism、Boundary 等互补内容，合并重叠区域。必要时由 Agent 使用已有文件工具补读，不把整篇原文无条件塞入结果。

短 topic 可以按笔记分组；包含多个问题的大复习卡可按“文档＋问题章节”作为父实体。分组键不能仅用 `Mechanism` 等跨文档重复的小节名。

### 分组、去重与覆盖的区别

| 机制 | 解决的问题 | 不能自动解决什么 |
|---|---|---|
| 文档分组 | 一篇笔记占满多个返回名额 | 未召回文档、跨文件重复知识 |
| 内容去重 | review/topic/scaffold 中相同表述重复 | 同篇不同章节的互补证据选择 |
| 子问题覆盖 | 多个证据需求是否均有材料 | 候选是否相关、内容是否真实 |

先对当前 Top10 分组，只能得到其中已有的两三篇文档；需要扩大候选池或拆子问题才能获得新来源。内容去重不能简化成“同篇只留一条”。多子问题共享片段只返回一份，同时保留它支持哪些 query_id。

Q11 的目标是假设候选池已有状态机、Trace 等材料后，让 Router 文档不再占八个外层名额；这不是已经实现的结果。

## 5. 片段内容与中文处理

- 保留既有标题结构切块，先验证搜索与打包策略，再决定是否调整边界。
- 正文证据参与相关性排序；纯跳转文本的检索价值可另行评估，首版不解析链接或扩展引用链；来源和版本说明随证据保留。先做输出组织实验，不直接删除原始笔记或批量重建索引。
- 不按短 token 数一刀切删除，短定义、代码或边界句也可能是关键证据。
- 标题前缀对短片段的影响是待验证假设；现有前缀已经包含标题与标题路径，不默认去掉或再生成一遍 LLM 上下文。
- 中文分词、技术词典、完整标识符及组成词项应有一致的索引／查询规则；分词文本与引用原文分开保存。
- 知识主干、表达支架、复习材料用途不同。层级加权或过滤需按查询目的验证，不预设一个适合所有问题的固定优先顺序。
- 全文 SUMMARY、逐 chunk LLM 上下文和自动改写是可选增强，尚无本库收益结论。

### 默认与自定义方案

已确认的定制范围见[项目基线 §1.4](../project/baseline.md#14-默认方案与自定义2026-09-15-已确认尚未实现)。默认组合先围绕现有笔记结构做配套评测；自定义切块也可调整重要召回参数。

后续设计需列出每个可配置项的作用阶段、默认值、合法范围、成本影响及是否允许按次覆盖。候选池与融合等具体开放项尚待确定，不将其全部固定为内部参数，也不默认全部暴露给 Agent。

评测应记录实际生效的切块实现、配置及召回参数。比较召回策略时固定切块；比较切块时明确采用统一参数还是分别调参，避免把整套组合收益误称为单一算法收益。变更切块后哪些索引需要重建，须在同步设计中明确。

## 6. 数据与更新需要支持的能力

文档身份、缺失 ID 的写回顺序及切块前过滤规则见[项目基线 §1.1](../project/baseline.md)。实现导入、切块或定位时先读取该节。具体表结构留待设计：需明确 echo_id 与 note、chunk、父章节、原文位置、文件哈希、切块版本、embedding 模型及维度的关系，以及结果的 query_id 和召回来源。

增量更新建议先准备新片段与 embedding，再在成功后切换有效数据，避免先删除旧内容后模型调用失败。需要验证修改、删除、重命名、模型版本变更、重试及进程中断。SQLite 范围内的事务和扩展行为以真实测试为准。

检索两路应使用一致范围。向量全库 TopK 后过滤不等同于范围内 TopK。长操作应能响应超时和取消，分阶段记录候选数量、token 预算、耗时、模型调用及失败状态。

## 7. 实现前必须定下的参数与边界

- search 返回的是文档组还是平铺片段；source_id、note_id、section_id、chunk_id 如何关联。
- 每路候选池、文档组数、组内片段数、总 token 和子问题数量如何共同限制。
- RRF 按片段还是文档榜单融合；分组、rerank 和组内选择的顺序。
- 无结果、部分子问题缺证据、模型不可用时如何返回。
- 按 UUID 同步后，路径、内容与原文位置如何一致更新；使用前提见[项目基线 §1.3](../project/baseline.md#13-本地读取与同步边界2026-09-15-已确认尚未实现)。
- 默认切块与召回参数组合、自定义切块契约、重要参数清单与配置覆盖方式。
- 最小验收样本及实验比较预算。
