# QMD：搜索片段如何引导 Agent 补读

访问日期：2026-09-09。参考项目：[tobi/qmd](https://github.com/tobi/qmd)。本地代码：`references/qmd/`；固定提交：`dbfd0b4736aeaf761d1a16ca8e424f071df8feb9`。

证据等级：已阅读官方 README、实现和测试源码；未安装依赖、启动服务或执行测试。以下行为依据该提交静态分析，不是本地运行结果，也不证明在中文笔记上的效果。

## 一条调用链

QMD 的 MCP 暴露 `query/get/multi_get/status`。`query` 返回人读摘要及 `structuredContent.results`，每项含 `docid/file/title/score/context/line/snippet`。`line` 是命中在索引原文中的绝对行号，从 1 开始；没有 `end_line`、父章节范围或可直接传入下一工具的 `read_more` 对象。[结果构造](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/mcp/server.ts#L373-L395)

它在工具描述中直接教 Agent：围绕命中调用 `get(file, fromLine=max(1,line-20), maxLines=80, lineNumbers=true)`。`get` 支持独立参数，也支持 `file.md:100:40` 简写；显式参数优先。初始化说明只列集合名称、能力缺口和关键用法，把集合详情交给 `status` 按需读取。[补读指示](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/mcp/server.ts#L251-L257)、[动态说明](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/mcp/server.ts#L107-L163)

这里值得采用的是“在工具说明里给触发条件和下一次调用”，不是让每篇 Markdown 都携带操作指令。Echo 已决定由 Agent 拆子问题，不应连带照搬 QMD 的内部自动扩写；当前代码同时支持普通 `query` 自动扩写及调用方提供的 `searches`。[参数与分支](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/mcp/server.ts#L316-L370)

## 补读读什么、怎样继续

`get` 读取的是 SQLite `content` 中的完整索引文本，再按行切片，**不是即时读取磁盘文件**。它可以越过任何 embedding chunk 边界，适合补全文字、代码或前提；但接口没有父章节模式、预期版本校验或续读游标。未给 `maxLines` 时没有这个行数限制。[读取实现](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/store.ts#L4891-L4934)

`multi_get` 按文件限制大小，过大则跳过并建议单独读取；按 `maxLines` 截断时只追加“剩余多少行”的文字，没有结构化下一段参数。代码默认 64 KiB，README 参数表仍写 10240 字节，提示不能只抄文档表格。[批量读取](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/mcp/server.ts#L481-L544)、[README 参数表](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/README.md#L184-L202)

因此 Echo 可保留单一按行 `read`，由搜索结果提供父章节对应的范围参数，并返回实际范围、是否截断、下一次读取参数；无需专门增加一个“章节读取”工具。索引快照读取与实时原文读取仍需明确选定，不能把 QMD 的快照行号称为磁盘当前版本定位。

## 切块与原文定位：有基础，也有细节问题

QMD chunk 记录 `{text,pos}`，`pos` 来自原字符串切片；token 超限时递归子切块累加偏移。embedding 前才补标题文本，原始位置与模型输入分离。这是 Echo 自定义切块器可借鉴的边界，但 Echo 还要处理过滤 `echo_id` 后到完整原文件的映射。[原始偏移](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/store.ts#L357-L410)、[子块偏移](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/store.ts#L3301-L3307)、[模型前缀](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/llm.ts#L107-L118)

搜索展示重新抽取命中附近最多约四行、300 字符的片段，附 diff 式起点和前后剩余行数。需要注意一个静态可推断的问题：片段从命中前一行开始，先插入 diff header，再用“命中行”给整段编号，因此外层数字前缀不可靠地对应原文行号；字符截断后，header 的行数仍按截断前窗口计算。Echo 应把定位字段与纯原文分开，从实际返回范围生成行号，避免 Agent 解析这类混合字符串。[片段提取](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/store.ts#L5317-L5358)、[MCP 追加编号](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/mcp/server.ts#L380-L390)

## 身份、聚合与测试边界

QMD 的 `docid` 是内容哈希前六位，正文改变会改变标识；查短哈希有碰撞时取首项。纯改名且内容不变可以复用内容，但这不是稳定的笔记 UUID，也没有以预期版本固定后续读取的契约。Echo 应沿用已确认的 frontmatter `echo_id` UUID v4，另行表示内容版本。[ID 生成](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/store.ts#L2339-L2343)、[短 ID 查询](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/store.ts#L3370-L3388)

向量召回按文件保留距离最好的命中。它可以减少同文档占位，但也会隐藏同篇的其他证据；Echo 的综合题不应因此固定“一篇只留一块”，应保留子问题命中映射并在返回预算内选互补片段。[按文件聚合](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/src/store.ts#L4281-L4309)

测试源码覆盖按行读取、片段偏移，以及经 MCP 返回第 301 行命中。后一测试仅检查结构化 `line=301` 和 header 形状，不能证明整段展示行号逐行对齐；本轮未运行这些测试。[读取测试](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/test/mcp.test.ts#L483-L506)、[MCP 行号回归测试](https://github.com/tobi/qmd/blob/dbfd0b4736aeaf761d1a16ca8e424f071df8feb9/test/mcp.test.ts#L1130-L1149)

Echo 的直接收益是采用“简短说明＋有定位的搜索结果＋独立范围读取”；改进点是明确版本、实际返回范围和续读入口。QMD 的短哈希身份、默认整篇读取、混合展示编号及固定机械扩展窗口，不宜直接变成 Echo 契约。
