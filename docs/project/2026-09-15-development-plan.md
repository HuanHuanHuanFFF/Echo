# Echo 首版开发计划

日期：2026-09-15。状态：**五阶段划分已获用户同意，开发尚未开始。** 本文记录阶段目标、职责边界与验收条件；具体接口、依赖版本和默认参数在对应阶段落定并验证。

## 1. 依据与变更规则

产品范围见[项目基线](baseline.md)，检索机制与定位建议分别见[检索设计](../design/retrieval.md)、[Agent 接口](../design/agent-interface.md)。

本计划接替项目基线中“下一轮决策”的讨论顺序，作为开发阶段划分；原有产品决定继续适用。后续执行遵循 [AGENTS.md](../../AGENTS.md) 的文档优先级：用户最新明确需求优先；同一范围的新有效文档修订旧计划或与其发生阻断级冲突时，以新文档为准。新文档注明日期、状态、替代范围和相关旧文档，旧文档保留为历史，无需全面回改。日期较新的调研或未确认建议本身不推翻已确认需求。

本次任务仅编写计划，不执行开发、修改个人笔记或重建其索引。

## 3. 阶段 1：工程基础与接口

**实现与职责**

- 初始化 TypeScript 工程，确定运行、构建、格式和测试配置。
- 验证 SQLite 全文与向量扩展在 Windows 的安装、加载、写入与查询；锁定实际验证过的依赖版本。
- 确定 chunker 输入输出、索引与检索模块职责、配置结构和部分覆盖规则。
- 跑通 MCP 最小调用；明确 embedding 接口，并确定后续真实模型接入方式。

**边界**：使用隔离样本和临时数据库；此阶段的 MCP 样例只验证连通性，不代表真实检索完成。接口应容纳完整自定义切块和重要召回参数，避免后续补接时改写整条流程。

**完成标准**：安装、构建、测试命令可运行；样例数据能完成数据库写入、全文及向量查询；真实 MCP 客户端可调用样例工具。模拟 embedding 的结果只用于接口验证，不能报告为真实语义召回效果。

## 4. 阶段 2：笔记导入、切块与同步

**实现与职责**

- 按已确认规则处理 UUID v4、头部过滤和原文件位置映射。
- 实现默认标题感知切块，以及用户自定义切块的加载和产物校验。
- 实现新增、修改、改名、删除的同步与索引更新，维护来源和片段身份。
- 明确切块规则／配置变化后的重建行为，以及同步失败后的可恢复状态。

**边界**：同步先以显式命令作为实现起点，自动监听不作为本阶段完成条件。UUID 用于识别文档，内容变化检测另行实现。笔记与索引操作先在隔离样本上验收。

**完成标准**：重复同步不重复入库；同 UUID 改名和改动后路径、内容、位置正确刷新；删除后无残留命中；默认与自定义切块均可索引；切块变更可正确重建；失败重试不丢失既有可用数据。ID 冲突处理须有明确、可验证的行为。

**建议小闭环**：UUID 与位置映射 → 默认切块 → 自定义切块 → 增量同步及恢复。

## 5. 阶段 3：混合检索与参数配置

**实现与职责**

- 实现中文笔记的 BM25 与向量召回、RRF 融合。
- 实现候选选择、去重和最终返回约束；区分内部候选数量与返回 topk。
- 落定重要召回参数的开放清单、默认值、合法范围和覆盖行为；支持与自定义切块配套使用。
- 保留必要的阶段诊断，区分未召回、排序／配额淘汰与返回预算不足。

**边界**：不要求开放任意召回算法插件。融合权重、候选数量、重排等具体配置在实现前逐项落定；重排是否纳入首版仍由实际需要决定。此阶段默认数值是评测起点。

**完成标准**：同一问题可比较单路与混合结果；配置变更可观察、可复现；非法配置被明确报告；topk 与 max_chunks_per_source 同时生效，不足时返回实际数量；合并或去重后保留准确原文定位。

## 6. 阶段 4：Agent 查询完整流程

**实现与职责**

- 将真实检索接入 MCP，接收 Agent 提供的查询及子问题。
- 确定独立子问题与同意图变体的组织方式、最终预算与结果归属。
- 返回片段、可访问路径与原文范围，供宿主文件工具补读。
- 处理部分失败、无命中、模型不可用以及必要的超时与取消。

**边界**：Echo 不拆问题、不生成答案；首版不提供专用读取工具或引用链导航。以笔记完成同步、本地文件可访问为使用前提。

**完成标准**：真实 Agent 可搜索并通过已有文件工具补读；多子问题的证据归属可追踪；失败与无命中可区分；真实客户端交给 Agent 的结果包含正确定位；整体数量、单篇数量和输出预算限制可验证。

## 7. 阶段 5：默认方案评测与使用交付

**实现与职责**

- 用固定 Markdown 笔记样本评估默认切块与配套召回参数，形成可复用默认配置。
- 对照 dense-only 与混合检索、来源限制等策略，记录证据覆盖、重复占位、延迟和累计上下文成本。
- 验证自定义切块与参数覆盖示例；完善安装、配置、同步、检索和常见故障说明。

**边界**：现有 12 题 Chroma 基线提供失败线索，不代表全库质量或 Echo 效果。比较检索策略时固定切块、语料、embedding 与预算；比较整套方案时明确变化项。使用个人笔记副本或原库的具体范围按当次授权执行。

**完成标准**：报告包含配置、样本、可复查结果与局限；用户可按文档从安装走到实际查询；默认方案有实测依据。效果未提升时如实记录原因与下一步，不以调参次数或功能数量代替收益。
