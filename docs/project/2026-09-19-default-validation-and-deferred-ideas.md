## 已确认方向和暂存事项

| 事项                     | 状态与边界                                                                                                                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 索引式预览减少无用上下文 | 用户要求记录、先留着。指查询相关的结果目录/预览，不是把整个数据库索引发给Agent。候选内容可包含路径、标题、短原文、范围，由Agent选择后通过宿主文件工具补读；具体格式未定，不新增专用读取工具 |
| 显式调整检索参数         | 延续用户决定：不传使用所选配置默认；Agent根据证据不足显式扩大topk、单篇数量或预算，不服务端静默放宽用户上限                                                                                 |
| 继续检索/游标            | 保留未返回候选、去除已返回块是待设计方向；跨页同篇上限累计还是每批重置，用户尚未决定                                                                                                        |
| 独立硬预算               | 用户提出由配置设不可越过的硬上限。默认预算与硬上限须区分；超限报错还是截至上限、具体数值、字符单位和计入范围尚待定。现有Schema允许值范围不等于已经实现该配置                                |
| 紧凑结果格式             | 去详细排名、合并重复来源元数据的本地格式估算有19.61% token空间，见调研及指纹；尚未实施，不代表整轮节省或Agent理解等价                                                                       |
| 子问题保留定位信息       | M-T23/M-T12已观察到丢实体或限定条件，作为Agent使用契约的待改进项；改写仅利用问题信息，不读取标准答案生成子问题；Echo仍不拆问题                                                              |
| MMR / rerank             | 两种独立候选选择对照，未确认采用；暂不与默认参数验证合并成组合网格，rerank模型/供应方另定                                                                                                   |
| 无答案与相似主题         | 产品验证缺口；返回相似片段不等于Agent幻觉或拒答成功。Agent作答、补读循环后续单独评测                                                                                                        |

本轮优先外部数据适配与默认方案验证；预览、分页、硬预算接口和新重排实现不属于本次文档交付。未来预览补读要同时报告首次/单次最大/全轮累计输入及证据恢复，不能只凭卡片变短判断有效。

## 下一步：先冻结协议，再按原因逐项调整

### 1. 数据适配检查

先查数据版本、许可、完整语料规模、官方划分与标签、文档ID、原始结构和行范围映射、模型输入长度，输出下载/索引规模估计及可复跑清单。数据、模型返回与索引继续放E盘实验目录；仓库保存协议、脚本和公开结果，不修改原笔记或旧Chroma。

正式评测保留选定领域完整干扰语料，不只索引命中文档。抽查询可以作预声明试跑；缩减语料必须另命名子集，不能比较完整官方榜单。适配调试用训练/开发划分或隔离样本；没有可用开发划分时独立划分并公开ID，留出不参与修适配或调参。自建笔记留出按来源/意图分组，避免近重复题泄漏；官方任务共享语料时遵循官方划分，不因此篡改语料。

### 2. 两种口径独立运行

- 官方检索：保持官方固定文档/片段及ID，用原问题和官方评分脚本；检查dense/BM25/hybrid及排名，按官方K值报告。不能将top10产品输出冒充Recall@50，也不能把固定片段模式称为完整产品默认。
- Markdown产品：完整文档按策略切块，实际请求/输出受同一topk、每篇上限、JSON预算限制，检查返回原文的事实与定位。公共片段若重建全文，必须有可靠源映射与重新验证的证据标签，否则不用它证明切块收益。混库30%仅约束笔记测试，不改官方分布。
- 保留用户需要的固定子问题对照，与官方原问题直搜分开报；子问题只根据题干生成并冻结，所有方案共用，不用答案要点/oracle字段指导检索或拆题，不运行多轮上下文分析。

### 3. 产品默认的最小比较顺序

| 顺序   | 唯一变化                  | 目的                               |
| ------ | ------------------------- | ---------------------------------- |
| P0     | 无：heading-1000 / RRF30  | 当前实际默认起点                   |
| P1对P0 | 仅换markdown-structure-v1 | 隔离新综合切块贡献                 |
| P2对P1 | 仅RRF30→10                | 检查候选融合参数能否跨资料保持收益 |

其余参数沿用上表，每轮先小范围检查适配，再报告完整预声明范围，不把三臂差异混称单因素。单路诊断沿用相同切块/预算，仅切mode；官方固定片段不能用于P0/P1切块结论。

先分清没有进候选、排序靠后、同篇/topk限制和预算排除，再决定改一个参数。RRF、权重、阈值、候选数不预开网格；候选已够用时不优先加候选。常用递归切块基线在P0/P1/P2可复跑比较后单列，MMR/rerank留后续独立批次。

### 4. 何时能采用新默认

看分数前确定主要指标、允许成本和实质性退化范围，用开发材料选方案、未调参资料验证。同模型、同问题、同输出预算上限比较，另报实际消耗，公开分库/题型结果、成对差值与区间、token/API用量和包含真实模型调用的延迟。

“更优秀”可体现为更高完整证据覆盖，或在事先定义的质量容忍范围内降低成本；不能以单一高Hit、仅胜弱BM25或差值未显著就宣称领先/等效。标签核查等价证据，独立人工核验不足时明确披露。旧最终200题已暴露，保留冻结分数，不能再拿它优化后称为新盲测。

正式评测的实现与结果交付沿用huan-dev及既有两位Luna/max独立复核要求；本次仅文档变更不启动评测或额外子线程。
