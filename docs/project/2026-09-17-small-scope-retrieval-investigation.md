## 下一次第一项：子问题拆分会不会降低效果

### 已核实机制与疑点

[requestFor](../../src/retrieval-evaluation.ts)在有subquestions时只发送子问题，不附带父题原问句；
[packResults](../../src/retrieval.ts)按各子问题候选的名次轮流取证据，所有子问题共享总topk、每源上限和完整JSON预算。

因此先检查以下假设，尚不认定已发生退化：

1. 子题是否遗漏主体、版本、时间、否定、比较关系或适用条件；原问句没一起发送时，这些信息是否真的丢失。后续若改写子题，只能补回父题已给的信息，不预填需要检索的答案。
2. 本来一个主题就能回答的问题是否被过度拆开；多个子题是否召回同义片段、挤占其他必需事实的位置。
3. 子问题数量、顺序与共享配额是否造成竞争；输入和归属元数据变长，是否挤压可返回正文。
4. 拆分后的每路候选池和API请求更多，收益或退化来自文本变化、候选扩大还是最终拼装，需要分开诊断。
5. 子题覆盖统计依据matched_query_ids归属，不等于该子题单独检索也能获得相同结果；首要看父题全部必需事实是否齐全。

### 首轮最小对照：先6题、两组

- 从已有33道拆分开发题中，按问题结构选6道：覆盖多目标、比较/条件、可能无需拆分的情形，兼顾现有成功和失败；选定ID与理由后不按新得分换题。
- A组：只发送原始完整问句。B组：只发送原先冻结的子问题。每组每题一次调用，总计最多12次父题执行；API请求数须另按子题数计算。
- 固定同一语料/索引、事实标签、模型、分词、chunk和召回参数。先沿用原chunk对照的heading-1000＋hybrid、topk8、每篇2块、累计12000字符；本轮不同时切到每篇3块。
- 两组都使用同一个父题总预算，不给每个子题分别分配12000字符。记录实际请求/响应字符、API用量与缓存条件。
- A组输入做独立实验副本，原冻结题库不改；父题必需事实和允许替代证据保持一致。
- 先给6行逐题对照：完整/部分/缺失、得失事实、来源/行范围、重复证据、配额/预算排除、请求数与累计字符。父题覆盖是主指标，子题归属作诊断。
- 这一轮评价“当前固定拆分方式的整体影响”，不单凭分差断言某一个机制，也不外推到所有Agent实时拆分。
- 看完这6题再决定是否扩大，或另测一个已定位因素。不要同轮追加“原句＋子题”、顺序重排和多组参数。

这是有意改变请求结构的对照；[现有比较器](../../src/retrieval-comparison.ts)要求相同数据/请求，不能绕过校验直接套用。
小样本先按相同父题事实对齐展示逐题结果，不为这一轮新建大型统计框架。若需正式统计，再单独验证相应方法。

## 其他可能影响效果的因素：先排队，不同时测

| 优先顺序   | 因素                       | 要分清的问题                                                                                     | 最小排查方式                                                             |
| ---------- | -------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 随子题检查 | 预算与结果拼装             | 是没进候选、排序靠后，还是被topk/单篇限制/JSON预算排除；全局排除计数不能唯一归因某个事实         | 先看已有失败题的候选、最终范围和字符分布，证据不足就标未知               |
| 随子题检查 | chunk边界与标题上下文      | 标题/条件与正文是否分离；段落、列表、表格、代码是否被截开；重叠是否产生重复占位                  | 各抽少量已知得失例，核对原文行和返回正文/heading_path，不批量改chunk规则 |
| 后续逐项   | 同源配额、近重复与混库干扰 | 每篇2块是否不足；增加后是否挤占跨来源证据；相似片段是否重复占topk                                | 在明确案例上只改一次来源上限，分别看同源与跨源题                         |
| 后续逐项   | 两路候选、RRF与权重        | dense已有的正确证据在哪一环节丢失；候选60/60是否已截断；等权融合是否引入干扰                     | 先追踪同一事实的两路名次和最终结果，确认原因后只改一个参数               |
| 后续逐项   | BM25分词与标题权重         | 中文术语、英文标识符、缩写是否分对；标题或扩展词项是否压过正文匹配；长查询词项限制是否有影响     | 查看少量查询/文档的实际词项及命中字段，不先换整套分词器                  |
| 后续逐项   | embedding输入与阈值        | 标题拼接、文档/查询前缀是否合适、实际输入是否完整；当前相似度0.3是否丢失有效证据或留下过多弱证据 | 固定qwen3.7/1024先查实际输入、相似度分布和漏召回例，不先换模型           |
| 单列诊断   | 无答案、近似主题与版本差异 | 候选只是同主题，还是确实支持问题；版本/时间/条件相近造成的误命中                                 | 将5道无答案题与有答案题分开看，不直接用非空率当答案错误率                |
| 贯穿复核   | 标签与计分口径             | 整行覆盖是否低估语义充分的返回；heading_path上下文、等价证据是否被遗漏；是否把定位指标当答案质量 | 对少数案例核查；疑似标注问题另记、复审并版本化，不按低分回改已冻结标签   |
| 固定条件   | 数据形态与复现环境         | 短TIL/长课程/AI整理笔记是否主导结论；语料版本、索引就绪、ICU/模型、缓存与降级是否变化            | 按库分列并核对快照；已有批次无运行失败，不能凭延迟差异推断召回改善       |

机制与配置依据：[检索实现](../../src/retrieval.ts)、[分词实现](../../src/lexical.ts)、[切块实现](../../src/chunker.ts)、[embedding调用](../../src/embedding.ts)、[单轮评测契约](../design/retrieval-evaluation.md)。
Agent仍负责拆题和答案，Echo只返回证据；此处未增加Agent动态改写、回答生成或多轮上下文实验。
