本文接替 [2026-09-15 待调整草案](2026-09-15-pending-adjustments.md) 中的以下范围：取消“同一切块实现外配多套参数档”的方案；召回配置由固定一份改为可保存多套；主入口按 ID 选择配置。多模型与切块隔离、索引指纹、仅返回证据等既有决定继续适用。当前代码与 [配置契约](../design/configuration.md) 尚未迁移，不把本文当成现有运行接口。

## 已确认的组织边界

### 切块策略：一个 ID 对应完整的固定实现

- 每份策略实现共同的 Chunker 接口，但有自己的 ID、实现文件和固定规则参数；文件名去掉扩展名必须等于策略 ID。
- 改变规则中的数字也作为新策略发布。例如 heading-1000.mjs 与 heading-500.mjs 是两个策略；不通过外部 JSON options 或单次调用覆盖同一策略的切块参数。
- 取消独立的“切块配置 ID 引用策略 ID 再覆盖参数”这一层。主配置直接选择策略 ID。
- 可以在代码内部复用公共辅助函数，复用不改变对外“一 ID 一完整策略”的边界。
- 保留已经确认的代码、版本和有效规则指纹。新策略使用新 ID；指纹用于检测同 ID 内容被意外修改、模块依赖变化或索引不兼容，不作为鼓励同 ID 随意调参的入口。

这项最新需求替代此前关于切块参数在配置中部分覆盖的提案；模型与召回配置的字段覆盖能力不因本项自动取消。

### 模型配置：所有 embedding 调用设置放在一起

模型 ID、API 模型名、向量维度、URL、API key 的配置归属、请求超时、批量大小、文档/查询前缀、是否发送 dimensions 等都属于同一个 embedding 配置文件。允许保留多份，通过配置 ID 选择。

凭据实际保存方式仍沿用当前实现：文件保存 api_key_env 引用，key 值从环境变量读取；用户已确认的是配置归属，尚未要求改成文件内明文 key。key 不参与向量索引身份。

### 分词策略：独立选择，只决定 BM25 词项

用户已确认将 Echo 的本地词项处理纳入策略。主入口增加分词策略 ID；不同策略可保留对应的 BM25 索引。文档索引与查询使用同一套分词策略，不混用不同规则生成的词项。

建议沿用切块策略的组织方式：tokenizers/ 下每个模块对应一个 ID，导出 ID 与文件名一致；策略包含算法及词典、停用词等相关规则，其版本化资源纳入指纹。具体接口和命名在集中实施时落定，不把这些建议当作现有插件能力。

分词处理的产物只用于 FTS/BM25。chunk 原文和 embedding 输入继续独立保存；embedding 使用文件名、标题路径和原文，不使用 BM25 的分词结果。因此更换分词策略不应重切块或重新调用 embedding。

### 召回配置：多套可选，与表身份无关

允许将 RRF、两路候选数量、权重、相似度阈值、topk、单篇上限和输出预算等保存为多份召回配置，通过 ID 选择。它们不绑定某个模型或策略、不参与数据库表名或索引身份，也不因为切换召回配置而重复切块或 embedding。

一次查询仍执行选择的设置，并遵守 topk 与单篇上限两个硬限制。单次 overrides 的优先级须在集中实现时明确，不能改变索引身份。

### 主入口：按 ID 选择本次运行组合

主配置引用切块策略 ID、分词策略 ID、embedding 配置 ID、召回配置 ID，加载对应文件。主入口保留数据库路径、目录及各配置文件位置；笔记扫描和数据库/服务运行控制放在专门的配置中，不内嵌各策略或模型的完整内容。

主入口不是保存进程实时计数的状态文件。用户已确认：切块、分词、embedding、召回四类活动配置热重载，从下一次查询开始采用新组合，不要求重启；在途请求继续使用其开始时的配置快照。数据库路径与服务运行参数按重启后生效处理。

## 扫描、初始化、切换与运行设置（用户已确认纳入）

### 数据源与扫描

增加包含/排除路径规则、单文件大小上限，并保留多知识库 ID 和根目录配置。建议放在独立的 config/sources.json，每个知识库可声明自己的扫描范围；具体字段和路径匹配语法在集中实施时确定。

过滤只影响索引范围，不删除原笔记。已有来源被新规则排除时，后续同步须按明确规则清除或使对应索引记录失效，不留下看似仍有效的旧命中。仅处理 Markdown 的产品范围继续适用。

### 初始化与配置管理命令

用户要求提供初始化指令和简单的配置切换指令。命令名称暂拟如下，当前尚未实现：

```text
echo-mcp init
echo-mcp config list
echo-mcp config show
echo-mcp config use --chunker heading-1000
echo-mcp config use --tokenizer icu-zh --embedding model-a --retrieval balanced
```

建议行为：

- init 创建目录、内置策略、默认配置/模型模板及基础数据库结构；重复运行保留已有自定义内容，不自动覆盖。初始化本身不导入个人笔记或调用 embedding；sync 承担用户配置完成后的实际索引工作。
- config list 列出可用策略和模型/召回配置；config show 展示当前选中的 ID、文件位置及必要的索引状态，不展开真实 key。
- config use 支持只切换一项或同时切换多项；先校验全部引用，再一次性保存新的选择，失败保留旧选择。
- 切换只选择配置，不隐式重建或删除索引。新组合尚未同步时明确提示需要 sync；已有且有效的组合直接复用。
- config use 对四类活动配置触发热重载，已有 MCP 服务从下一次查询采用完整的新配置；在途请求不混入新配置。记录并展示每次请求实际使用的组合。数据库路径与服务运行参数变化另行提示需要重启。当前服务只在启动加载配置，热重载尚待实施。
- 重载解析、ID 校验或兼容性校验失败时，不发布部分配置；明确说明切换未成功或当前仍使用哪份配置。新组合缺索引时报告需要同步，不静默用其他组合代替。

使用 echo-mcp 作为命令名示例，避免与 Windows shell 自带的 echo 混淆；最终安装入口与文档需实测。

### 存储路径与运行控制分开

用户要求数据库/服务并发等运行控制有专门的配置位置。建议：

| 配置                                                    | 归属                    |
| ------------------------------------------------------- | ----------------------- |
| 默认策略/模型/召回 ID、数据库路径、各目录与配置文件位置 | echo.config.json 主入口 |
| 知识库目录、包含/排除规则、大小上限                     | config/sources.json     |
| 整个搜索的超时、最大并发、SQLite 锁等待超时等运行控制   | config/runtime.json     |
| 单次 embedding 请求超时、批量大小、模型调用相关设置     | 对应 embedding 配置     |

搜索并发与数据库锁等待是不同设置，分别命名。当前 [database.ts](../../src/database.ts) 固定 busy_timeout=5000；搜索超时/并发已在 runtime 中，拆分文件后继续保留。具体开放的数据库参数以正确性验证为边界，不把所有底层 pragma 都做成配置。

### 日志

用户已同意增加日志级别、日志位置和最大文件大小。建议统一放在 config/logging.json，并定义轮转/保留上限；MCP 标准输出保留协议用途。默认日志不记录 key 或笔记正文。日志级别、路径和轮转设置不参与索引身份，也不触发重建。

## 文件与表映射建议

以下文件名、字段名和表名格式是实现草案，供集中改动时统一落定：

```text
chunkers/
  heading-1000.mjs
  heading-500.mjs
  paragraph.mjs
tokenizers/
  icu-zh.mjs
config/
  embedding/
    model-a.json
    model-b.json
  retrieval/
    balanced.json
    broad.json
  sources.json
  runtime.json
  logging.json
echo.config.json
```

主配置中的选择部分示意：

```json
{
  "active": {
    "chunker": "heading-1000",
    "tokenizer": "icu-zh",
    "embedding": "model-a",
    "retrieval": "balanced"
  }
}
```

表映射以所选 ID 组合为可读标识，另保存并验证完整指纹：

| 数据             | 映射所需信息                                              | 不参与映射         |
| ---------------- | --------------------------------------------------------- | ------------------ |
| chunk 与来源快照 | chunk 策略 ID、规则指纹                                   | 模型配置、召回配置 |
| BM25/FTS         | chunk 策略 ID、分词策略 ID、规则与分词指纹                | 模型配置、召回配置 |
| 向量             | chunk 策略 ID、embedding 配置 ID、维度、相应规则/模型指纹 | 召回配置、key 值   |

表名可呈现为 vec_<chunk_id>_<embedding_id>_<dimensions>_<fingerprint>。加载器校验 ID、限制表名字符，并通过登记表验证完整身份，避免名称拼接后碰撞或同 ID 内容变化时误用索引。

来源版本与同步状态仍须按索引保存。不同策略与模型的已有索引同时保留；只有选中且兼容、来源状态有效的组合可供对应查询使用。缺失组合不自动调用全部模型生成索引。旧配置迁移需要明确处理被取消的 chunker.options，不能静默忽略旧参数。

## 哪些变化影响哪些表（用户已确认的目标行为）

用户于 2026-09-16 确认下面的依赖关系。以下假设语料和其他配置不变；切换至已存在且有效的组合时复用，不重复建立相同索引。

| 变化                                                    | chunk/来源快照     | BM25/FTS                | 向量                        | 是否参与分表                          |
| ------------------------------------------------------- | ------------------ | ----------------------- | --------------------------- | ------------------------------------- |
| 切块策略变化                                            | 新策略的一套       | 为新 chunk 建立对应索引 | 为新 chunk 建立选中模型向量 | 是                                    |
| 分词策略或其规则资源变化                                | 复用               | 建立该分词策略的索引    | 复用                        | 仅 BM25                               |
| 模型、维度或影响向量语义的配置变化                      | 复用               | 复用                    | 建立对应模型索引            | 仅向量                                |
| RRF、标题评分权重、候选量、topk、返回预算等召回参数变化 | 复用               | 查询时应用              | 查询时应用                  | 否                                    |
| key 轮换、API 请求超时、批量大小、服务并发变化          | 复用               | 复用                    | 复用                        | 否                                    |
| 笔记内容修改或删除                                      | 同步更新受影响来源 | 更新或使旧数据失效      | 更新或使旧数据失效          | 更新原组合的数据，不因此生成新策略 ID |

各表的可读映射：

```text
chunks_<chunk_id>_<规则指纹>
fts_<chunk_id>_<tokenizer_id>_<规则与分词指纹>
vec_<chunk_id>_<embedding_id>_<维度>_<规则与模型指纹>
```

实际表名只使用受限字符；完整 ID、维度和指纹在登记表校验。召回 ID 不参与任何索引表身份；分词 ID 只参与 FTS 表身份，不放进 chunk 或向量表名。

当前 [sync.ts](../../src/sync.ts) 把 chunker、lexical、embedding 指纹合并为一个同步判断值，分词配置变化会连带重建 chunk 和向量。上述依赖拆分属于待实施改造，不能把“分词只更新 BM25”描述成当前代码已具备的优化。验收需验证更换分词策略后 chunk/向量记录保持不变，且 embedding API 调用为零。

## 当前 BM25 的事实与改造边界

2026-09-16 已核对当前代码：

1. [lexical.ts](../../src/lexical.ts) 在本地做 NFKC 规范化、Intl.Segmenter 词分割、汉字双字组合、技术标识符拆分及固定停用词过滤；自定义词典补充词项。词项编码后交给 FTS5，原文另存。
2. [store.ts](../../src/store.ts) 创建 SQLite FTS5 的 title/body 两列索引；[retrieval.ts](../../src/retrieval.ts) 调用 bm25(chunk_fts, title_weight, 1) 排序。Echo 没有自己重写 BM25 评分公式；sqlite-vec 用于向量计算。
3. 当前可配置 lexical.locale、lexical.dictionary、标题字段权重 title_weight 和 BM25 候选量。默认分别为 zh-CN、空词典、2、60；正文评分权重为 1。分词算法及停用词表当前不支持任意插件替换。
4. SQLite FTS5 的 bm25() 支持列权重；其 k1=1.2、b=0.75 是固定常量，不是 Echo 已开放参数。依据：[SQLite 官方 FTS5 文档](https://sqlite.org/fts5.html#the_bm25_function)，核对日期 2026-09-16。

“分词如何切词”和“BM25 怎样给匹配项评分”是不同层。分词/词典改变会影响 FTS 中保存的词项，需更新相应索引；标题权重、候选量等查询参数不要求更新词项。

用户最新已确认将分词纳入策略；策略目录、模块接口、索引隔离与加载方式尚未实现。本轮只记录组织方式，不立即替换现有分词算法。

## Agent 易用性（用户明确要求，必须验收）

这项要求约束工具契约、返回信息、错误恢复和验证方式，具体落实如下：

- 就绪状态下，普通查询只需 echo_search 的 query；不强制先调用 status、列配置或手工填写策略/模型/表名。复杂问题可使用已有 queries/variants 契约。
- 工具说明和输入 schema 足以让首次接触的 Agent 正确调用；工具名、字段和状态保持一致，默认值承接用户选中的配置。
- 返回直接可用的原文、绝对路径、行范围、来源版本与子问题归属；实际使用的配置组合可追踪。常规输出保持紧凑，完整上下文预算包含必要元数据和错误诊断。
- 故障返回能区分无命中、未配置、缺索引/需同步、模型不可用、部分失败和繁忙/超时，并提供结构化原因及可执行的下一步；保留仍可使用的证据。不能要求 Agent 根据含糊报错猜测是否要重试或重建。
- 热重载后新查询明确采用新组合，在途查询保留旧快照；不让 Agent 在一次结果中得到混合配置或错误定位。缺失组合明确提示，不暗中回退成另一个组合。
- Agent 继续只通过 Echo 检索证据，使用宿主文件工具补读；同步、持久配置切换等管理操作保持显式的 CLI 工作流，不因追求易用性就增加自动写入或隐式模型调用。

验收包含真实 MCP 客户端及 Agent 使用流程：正常查询、独立子问题、原文补读、空结果、模型失败、缺索引、配置切换后的下一次查询。至少一次让 Agent 仅依据工具说明/正常使用文档完成流程，观察是否需要额外解释、是否能选对下一步，并记录调用/重试次数和输出预算；不能只以 SDK 握手或模拟向量测试宣称 Agent 易用或真实语义有效。
