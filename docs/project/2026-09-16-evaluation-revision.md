## 交付目标

- Echo 面向本地 Markdown 笔记、个人资料和个人知识库；优秀默认组合是主要交付，自定义能力是补充。
- 同一默认 chunk、分词、模型和召回配置跨库测试，只更换资料范围和数据库位置。单库定制成绩单列。
- 产品质量和可核验的面试材料同等重要。题量不是认可保证；只讲实际验证的收益、代价、退化和限制。
- Agent 拆问题、调用宿主文件工具并回答；Echo 只提供证据。不新增专用读取工具、引用链导航、远程文件读取或 rerank。
- 普通 CI 继续使用隔离样本，不依赖个人笔记或模型密钥。

## 开始执行的顺序

1. 筛选真实笔记来源，记录许可证、固定版本、规模、结构、语言及同源关系；准备独立库与混合库清单。
2. 建立原文事实标签、来源位置和意图分组，形成100题开发集与200题锁定集；先审核再看检索结果。
3. 对评测驱动器做小样本校验，落实累计上下文和实际API用量记录、请求额度保护及失败保留。
4. 在开发集先比较两套切块，再做BM25/dense/hybrid对照与单组参数实验。保留失败尝试。
5. 冻结默认组合和基准后执行最终评测；另记录Agent实际任务和工程回归，不能与检索题分母混用。
6. 由两位独立审查者复核结果、统计和结论边界，形成可重跑入口、逐题结果和面试可用案例。

资料方向为3–4份独立来源、约500–800篇Markdown，具体仓库、篇数和抽样清单尚待审计；
不为凑数重复改写问题，也不预先用AI把所有原文改成同一种模板。
人工抽查约30题是待用户选择的建议，未实际执行就不标为人工金标。
额外20个Agent任务是执行建议，不替代已确认的300题检索验收。

模型连通已经验证，但完整真实语料索引、题集标注、评测驱动器和效果比较仍未完成。
完整API运行需先记录输入规模和本轮请求额度；一次短文本探针不等于整库评测。
当前状态及证据见[准备验证快照](../evals/2026-09-16-evaluation-readiness.md)。

## 文档与本地实验的职责

仓库docs是技术决定、协议和审阅用验证摘要的正式入口；E盘可以保留同步副本与运行说明。
后续先更新相应仓库文档，并记录同步版本，防止两份方案分叉。
私有语料、标签、完整MCP返回和生成索引留在本地；公共仓库只收不含私有正文的协议、
参数、汇总和来源审计。公开原文或原始实验数据另按适用授权处理。
源码改动走后续独立开发分支；本轮文档同步不改已安装的990644e运行版本。
