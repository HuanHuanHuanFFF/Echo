# 由 Agent 配置 Echo MCP

适用于用户让你安装、初始化或接入 Echo 的任务。先完成可执行的本地准备，再集中告知用户缺少的外部条件；条件齐全后继续同步与验证。本文只指导配置，不要求重新开发 Echo 或运行评测集。

发布状态：本文面向 `@huanf/echo@0.1.0`，随发布准备交付。若 npm 尚未提供此版本，报告安装阻断；不要安装名称相近的其他包。用户已有可用安装时可继续本地配置，并说明实际版本。

## 1. 先完成本地初始化

1. 从当前任务确定配置工作目录，默认使用用户打开的工作目录。检查现有 `echo.config.json`、Echo 安装和 Node.js 版本。要求 Node.js `>=24.15.0 <25`，已验证 Windows x64 / Linux x64。安装缺失时执行 `npm install -g @huanf/echo@0.1.0`；按宿主权限规则处理运行环境安装。
2. 在选定目录执行 `echo-mcp init`。已有主配置时先读取并复用，只补本次任务需要的设置。初始化创建本地配置与数据库，不导入笔记、不调用模型；缺少 API key 不妨碍这一步。
3. 读取生成的目录 README 和 `echo-mcp config show` 输出，确认主配置的绝对路径、活动策略、数据库和来源范围。后续命令统一带 `--config "<主配置绝对路径>"`，避免因工作目录不同操作另一份知识库。

完成标准：配置可加载、实际工作区已确定。运行环境确实缺失而无法初始化时，明确说明阻断，继续完成不依赖它的配置草稿；不得声称已经初始化成功。

## 2. 完成不依赖外部信息的配置

### 笔记范围

将用户明确提供或当前任务已确定的笔记目录填入 `config/sources.json`。目录尚不明确时，保留未配置状态，加入最后的缺失清单；不要把整个磁盘自动当作笔记范围。

例如，笔记位于配置目录的 `notes` 子目录时：

```json
{
  "collections": [
    {
      "id": "notes",
      "root": "notes",
      "include": ["**/*.md"]
    }
  ]
}
```

路径相对主配置所在目录解析。若范围包括配置目录本身，排除实际的配置、切块和分词目录，避免把生成的说明当作笔记。显式 `exclude` 会替代默认排除规则，应同时保留隐藏项、`node_modules` 等原有排除项；规则见[配置契约](../design/configuration-profiles.md)。

不同工作目录默认隔离配置与数据库；同目录仅换主配置文件名不会自动隔离。复用现有设置时核对实际路径。

### Embedding 与默认检索

保留默认切块、分词和召回方案，先完成接入。默认混合检索需要外接 **Embedding 模型**，不是对话模型，也不要求下载本地模型。

读取 `config/embedding/default.json`（已有工作区则读取当前选中的模型配置），复用用户已经指定的信息：

| 信息     | 配置要求                                                                               |
| -------- | -------------------------------------------------------------------------------------- |
| 服务地址 | `base_url` 指向 OpenAI 兼容服务的基础地址，不含末尾 `/embeddings`                      |
| 模型     | `model` 为提供方实际支持的 Embedding 模型 ID                                           |
| 向量维度 | `dimensions` 与该模型实际输出一致；按提供方文档核对                                    |
| API key  | `api_key_env` 保存环境变量名，默认 `ECHO_EMBEDDING_API_KEY`                            |
| 兼容选项 | 服务不接受维度请求字段时设置 `send_dimensions: false`；模型要求前缀时配置文档/查询前缀 |

缺失信息保留待配置，不把示例地址、模型名或猜测的维度写成有效配置。检查指定密钥环境变量是否存在即可，不回显密钥，也不遍历其他项目寻找凭据。为用户说明怎样向实际 MCP 宿主提供环境变量；另一个终端设置的变量不会自动进入已经运行的宿主，Echo 也不会自动加载任意 `.env` 文件。

用户尚未选择服务时，集中说明需要支持 OpenAI 兼容 `/embeddings` 的服务，以及模型 ID、维度和 API key。需要推荐具体模型时，结合资料语言、预算与提供方当前官方文档给出建议，区分建议和已确认选择；历史评测模型不是必选项。用户明确只需本地关键词检索时，才将检索模式设为 `bm25`，并说明尚未启用语义检索。

### MCP 接入准备

识别用户当前使用的 MCP 客户端，按该客户端支持的格式添加 Echo，保留已有服务器配置。客户端不明确或配置入口不可写时，先准备好下面的条目，把需要用户操作的部分加入缺失清单。

```json
{
  "mcpServers": {
    "echo": {
      "command": "echo-mcp",
      "args": [
        "serve",
        "--config",
        "/absolute/path/to/knowledge/echo.config.json"
      ]
    }
  }
}
```

替换为初始化所得的真实绝对路径，保证宿主能找到命令并将密钥环境变量传给 Echo。Windows 宿主若无法启动 npm 的 `.cmd` 入口，使用本机 Node 可执行文件的绝对路径作为 `command`，将 `npm root -g` 所定位包内的 `@huanf/echo/dist/cli.js` 绝对路径放在 `args` 首项，然后保留 `serve` 和 `--config` 参数。检查实际安装位置，不猜测路径。

完成标准：已知信息已配置，未知信息已列出；接入条目已写入或已准备为可直接使用的片段。已有配置与用户资料保持其原有范围。

## 3. 本地准备完成后，集中告知缺失条件

只列仍然缺少的项目，不重复询问用户已经提供的信息。例如：

- **已完成**：初始化、笔记范围、默认策略、MCP 接入配置或草稿。
- **还需要你提供**：尚未确定的笔记目录、服务地址、Embedding 模型 ID、输出维度。API key 通过宿主环境变量或其密钥设置填写，不要求粘贴到聊天。
- **还需要你操作**：仅客户端界面、登录或重启等 Agent 无法执行的部分，并给出具体入口或操作。
- **接下来会做**：同步与检索验证。同步会为缺少 `echo_id` 的笔记补写 UUID；API 模式会将正文和查询发送给已选服务，可能计费。已有授权直接沿用，范围或费用尚未获授权时在这里一并确认。

条件已齐全且授权明确时直接进入验证，不为固定流程制造额外问答。缺少外部条件时报告“本地准备完成，待补齐……”，而不是“Echo 已可用”。

## 4. 条件齐全后，同步并验证

依次执行，替换占位路径和查询：

```sh
echo-mcp config show --config "<主配置绝对路径>"
echo-mcp sync --config "<主配置绝对路径>"
echo-mcp search --config "<主配置绝对路径>" --query "<来自已配置笔记的一条可核对问题>"
echo-mcp status --config "<主配置绝对路径>" --check-sources
```

确认同步成功、实际启用预期检索模式，返回证据与当前文件内容、行号对应。仅有 `embedding_configured` 或 `ready` 不证明模型调用正常；默认混合检索需以实际成功的同步和查询验证。

在目标 MCP 客户端中重新加载 Echo，确认可发现 `echo_search` 和 `echo_status`，再执行一次搜索并核对原文。CLI 成功而客户端尚未验证时，明确区分两者。连接失败根据实际错误修正命令、路径、环境或 API 配置，保留成功部分；不要用静默切换为 BM25 掩盖模型问题。

交付时简要列出：实际配置与笔记范围、模型和维度（不含密钥）、检索模式、CLI/MCP 验证结果、仍需用户完成的事项。提醒编辑笔记后执行 `echo-mcp sync`；`echo_status` 的 `check_sources: true` 只读检查变化，不同步。答案生成和原文补读继续由 Agent 与宿主文件工具负责。
