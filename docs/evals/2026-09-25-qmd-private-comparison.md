# Echo 与 QMD：私有 200 题首轮对照

日期：2026-09-25。状态：**QMD 2.8.3 原生 MCP 的无重排与本地重排各 200 次父题查询已完成并复核**。这是已开卷的产品工作流对照，不据此修改 Echo 默认配置，也不把不同模型条件解释成切块或检索算法的单变量胜负。

## 固定范围与执行条件

使用[产品对照语料冻结](2026-09-22-product-comparison-protocol.md)的五个隔离范围：A 50、B 35、C 25、D 30、混合 60，共 200 道父题，其中 196 道可答、403 个必需事实、4 道无答案。保留原题和已冻结的子问题，不生成新题、不联系对话上下文。五个 QMD 索引分别确认了 150/22/165/27/364 个 Markdown 文件和 192/162/176/112/642 个向量块；混合范围与单库有重叠，不能将文件数相加当成不同文档数。输入是 E 盘测试副本，未写原笔记或旧 Chroma。

QMD 安装版本为 `@tobilu/qmd@2.8.3`，embedding 用本地 `Qwen3-Embedding-0.6B-Q8_0`，重排用本地 `Qwen3-Reranker-0.6B-Q8_0`；GPU 后端为 Vulkan。每道父题向原生 MCP `query` **调用一次**，传入全部固定子问题的 `lex` 和 `vec` typed searches（至多 6 个），`limit=10`、`candidateLimit=40`，分别运行 `rerank=false/true`。这个接口会合并子查询，但不会执行 QMD 文本 `query` 的自动扩展；没有使用 `hyde`。QMD 的查询结果是每篇约 300 字的带行号预览。本轮未调用它的 `get`/`multi_get`。

对返回结果统一施加 `topk=10`、每篇最多 6 条、请求加响应最多 20,000 个 UTF-16 字符，超过预算跳过该项。该预算计的是标准化评测载荷，不含完整 MCP 协议封套。Echo 参考条件沿用[前轮全量对照](2026-09-24-echo-dify-results.md)的 `markdown-structure-v1@1.0.1`、MiniSearch 7.2.0、BM25/向量权重 0.5/1、RRF10、候选各 60、相同 `topk`/每篇上限/预算；其 embedding 是 DashScope `qwen3.7-text-embedding` 1024 维。两边模型、索引单元和实际返回长度不同，所以本表是各自产品配置下的效果，不是同模型受控实验；每篇 6 条也是比较条件，Echo 产品默认仍为每篇 3 条。

## 结果

“完整文字证据”要求一次返回的片段覆盖题目全部必需事实的标注原文行；“正确文件”只要求返回文件包含这些事实，表示后续补读的机会，不表示 Agent 已获得答案。分母固定且三组共用标签。无答案题不计入 196/403 分母。

| 指标                              | Echo 参考 hybrid |  QMD RRF、无重排 |     QMD 本地重排 |
| --------------------------------- | ---------------: | ---------------: | ---------------: |
| 一次返回完整文字证据              |          190/196 |            4/196 |            4/196 |
| 一次返回事实覆盖                  |          393/403 |           19/403 |           20/403 |
| 找齐包含事实的文件                |   未按此口径复算 |          188/196 |          189/196 |
| 正确文件事实覆盖                  |   未按此口径复算 |          387/403 |          388/403 |
| 正确文件 Hit@10 / MRR@10          |   未按此口径复算 | 191/196 / 0.9349 | 191/196 / 0.9354 |
| 全 200 题平均标准化请求＋响应字符 |             8027 |             3781 |             3777 |
| MCP 查询错误                      |   未按此口径复算 |            3/200 |            3/200 |

| 范围（可答题） | RRF 正确文件完整 / 文字证据完整 | 重排正确文件完整 / 文字证据完整 |
| -------------- | ------------------------------: | ------------------------------: |
| A（48）        |                          47 / 3 |                          47 / 3 |
| B（35）        |                          35 / 1 |                          35 / 1 |
| C（25）        |                          25 / 0 |                          25 / 0 |
| D（30）        |                          29 / 0 |                          29 / 0 |
| 混合（58）     |                          52 / 0 |                          53 / 0 |

QMD 很常找对文件，但 300 字预览通常没有覆盖事实所在的完整行：重排条件下 189 道题已找齐相关文件，只有 4 道题在**预览文字**中直接找齐证据。这一差距主要反映 `query`→`get` 的分步接口，不能断言 QMD 结合补读后的答案质量低。重排比无重排多找齐 1 道题的文件、多覆盖 1 个文件事实和 1 个预览事实，完整预览证据没有增加；这批已开卷题目不支持重排有明显收益的结论。QMD 四道无答案题均返回了结果，单靠检索返回非空不能当作可答判断。

完整聚合及逐范围计数见[机器可读摘要](2026-09-25-qmd-private-summary.json)。严格完整行规则会把只出现关键词、却未覆盖整行的预览计为未命中，因而不能直接推断 Agent 读到片段时是否能猜对答案。

两种 QMD 条件各有 3 次原生 MCP 拒绝：固定子问题中的 `-词` 可用于词法排除，但 QMD 的 `vec` typed search 不接受该语法。它们都发生于可答题，关联 5 个必需事实；本轮没有改写冻结问题，按空召回计入原分母。若只看成功的 193 道可答调用，正确文件完整为 RRF 188/193、重排 189/193；这只是错误影响拆解，不替代主结果。所有已返回预览均能映射回冻结原文，映射失败 0。

QMD MCP 调用本身的记录延迟（服务已连接、已有模型缓存）为 RRF 中位 41 ms/P95 79 ms，重排中位 476 ms/P95 5635 ms。它不含建索引、启动、Agent 后续 `get`，且运行中可能复用缓存，不可与 Echo 端到端延迟直接比较。本轮查询和建索引均使用本地模型，新增外部 embedding/API 调用为 0。
