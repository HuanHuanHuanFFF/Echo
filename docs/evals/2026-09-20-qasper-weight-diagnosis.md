# QASPER低分原因：返回名额、段落精度与任务边界

日期：2026-09-20。状态：已完成冻结输出只读诊断，两位Luna/max独立复核通过。本分析解释[101题权重补测](2026-09-20-qasper-weight-pilot.md)，不更改其标签、参数、结果或产品默认。以下除明确标为全量的对照外，均为同一101题样本；基线为新综合/RRF30/BM25 0.5。

## 结论

QASPER暴露的主要短板是**标注证据没排进返回的前三块，以及块内附带了较多非标注段落**。候选覆盖与最终返回质量是两件事。调整BM25权重能交换少数靠前块，但没有解决证据选择的粒度和名额问题。

低F1也受任务口径影响，不过不是仅有口径问题：78道严格文本题中，基线仍有32道未找齐，其中29道没有精确命中任何标注段落。没有证据把主要责任归于模型语言能力、API失败、向量损坏或中文分词；本轮不据这些猜测更换模型。

此前[个人最终集](2026-09-18-final-four-arms.md)的91.33%是完整事实覆盖，不逐一惩罚附带的非标注段落；其中54题还有固定子问题。当前QASPER使用原完整问句、目标论文内检索和官方段落F1，因此不能称为同一指标从91%跌到20%。不过QASPER全量严格完整覆盖也只有约60%，仍表明现方案在公开论文任务上的适配和排序需要改进；不能只用口径差异解释。

## 1. topk10在这里实际最多返回3块

QASPER每题已给定论文，检索按该source_id过滤。topk10和每篇3同时约束，所以最多返回3块。基线101/101题发生来源上限排除，预算排除为0；六档606次请求加完整JSON的最大长度8058，低于16000。

将本轮0.5的32道严格不完整题关联到原P1同题候选诊断：

| 完整证据组首次齐备的融合排名前缀 | 题数 |
| -------------------------------- | ---: |
| 第4～5块                         |    9 |
| 第6～10块                        |   15 |
| 第11～25块                       |    8 |
| 候选池缺少完整证据组             |    0 |

32题全部有足够候选，却没在前三块集齐。按最小有效标注组，24题只需1段、6题需2段、2题需4段；段落数不等于chunk数。尤其24道单段题说明，问题不能全部解释为名额根本不够：前三块没有挑中需要的段落，是实质性的排序短板。这里的“首次齐备”是忽略打包限制、累计候选正文得到的严格证据覆盖，不是执行更大来源上限后的结果，不能宣称将每篇改成10就能实际补回24题。

[旧全量P1诊断](2026-09-19-public-qasper-results.md#不完整题为什么缺证据)也有相同方向：320道不完整题中317道池内已有完整组，另外3道是阈值过滤且BM25未补回。当前证据支持优先调查前三块排序与单篇名额，而非扩大60候选或16000预算。来源上限是直接截点，证据为什么落到第4～25位仍是排序质量问题，不能只归因于上限。

## 2. 找齐仍可能F1很低：返回单位比标签粗

官方Evidence F1按完整原始段落精确匹配，找对记分，多返回非标注段落降低精确率。三个chunk不等于三个段落。

基线全部101题平均返回5.49个完整段落；平均4.70个段落不在该题任一标注者的证据中（空白规范化后比较）。非标注不代表语义上完全无用，但它会增加上下文，并在该指标下受到惩罚。

真实例子：论文1912.06262，问题“what were their performance results?”，题目ID为9a8b9ea3176d30da2453cac6e9347737c729a538。两个标注者都只要求段落32；三个返回块覆盖14段，其中包含段落32，所以严格完整为真，但F1为：

\[
F1 = \frac{2 \times 1}{14 + 1} = 13.33\%
\]

返回内容包括结果、超参数搜索及讨论；正文中的短列表项也属于数据集的独立段落。即使只返回排名第一的结果块，也可能附带多个未标注段落，不能将额外内容全部归于topk。

在已经找齐的46题内，官方F1平均仍只有36.95%。这说明“尽量保留上下文的检索块”与“精确挑选必要段落”之间确实存在取舍。旧全量同参数只换切块时，heading→新综合使完整覆盖57.50%→60.00%，同时平均返回段落4.14→5.28、F1 26.43%→23.61%；新综合并非在所有质量指标上更好。

## 3. 图表、无答案和精确匹配只解释一部分下降

| 基线子集                      | 题数 | 官方Evidence F1 |
| ----------------------------- | ---: | --------------: |
| 严格文本证据题                |   78 |          23.20% |
| 其中：已找齐                  |   46 |          36.95% |
| 其中：未找齐                  |   32 |           3.44% |
| 图表/映射等不适用严格文本评分 |   16 |          12.37% |
| 全标注无答案                  |    7 |           0.00% |
| 全部                          |  101 |          19.88% |

“已找齐/未找齐”是78题内的子集，不能与78行再次相加。无答案题仍返回相近内容；官方空证据标签因此记0。Echo本次只做取证，没有Agent拒答，也没有执行选择性返回空证据的策略，不能把这个0解释为Agent全部答错。

排除23道非严格文本题后，F1也只有23.20%，所以图表和无答案不是全部原因。另作只读空白规范化诊断，基线仅2题变化，全体F1从19.88%变为20.37%，只差0.50个百分点。严格映射和官方字符串比较的差别不能解释主要差距；官方原分数保持不变。

## 4. 为什么调权重只有小幅变化

| 与0.5比较 | 完整题净变化 |    官方F1变化 | 返回块集合完全相同 |
| --------- | -----------: | ------------: | -----------------: |
| 纯向量    |           +2 | +1.76个百分点 |             43/101 |
| 混合0.25  |           +3 | +0.99个百分点 |             69/101 |
| 混合0.4   |           +1 | +1.05个百分点 |             91/101 |

RRF只根据两路名次加权，不判断段落是否真正回答问题。调权重可以改变三块的竞争，但不压缩块内多余段落，也不改变来源上限；对相同证据返回顺序的变化，段落F1本来就不敏感。各条件相对基线的成对区间均跨0，仍不能宣称稳定最优。

一个可定位的例子：论文2003.04642问分析了哪些MRC基准，正确的“Candidate Datasets”块是向量第2、BM25第21。权重0.5时没有进入返回前三，原融合前缀到第5才找齐；0.25时该块进入第3，恢复完整证据。0.5返回的“Factual Correctness”块则是BM25第1、向量第6，它与题目主题相关，却没有命中本题标注证据。相反，询问pivot-based baselines的题目在降低权重后丢失完整证据，所以不能简单去掉BM25。

## 后续优先级与未验证项

1. **先做来源上限的单变量小样本对照**：固定某一权重和chunk，比较每篇3与5，同时看完整覆盖、段落F1和实际上下文。更大上限可能补证据，也可能降低精度；本轮未运行。
2. **再验证更精确的证据排序/选择**：候选内rerank，或按原文段落定位的小检索单元加按需补上下文，直接针对“主题相关但不回答问题”和块内附带段落。只是候选方向，当前未证明收益。
3. **索引预览、游标和Agent补读继续留作后续产品设计**；它们可能减少一次输入的正文，但不会自动修正初次排序。无答案识别也需独立验收，不能拿当前余弦阈值当作答置信度。

本轮没有调参，没有新增检索或模型调用。诊断不证明系统达到优秀水平，也不把低段落F1等同于答案正确率；本轮没有人工判定标注外段落能否独立支持答案。
