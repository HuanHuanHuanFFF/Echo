# Du中文200题：分词与IDF单变量试验

日期：2026-09-20。状态：完整语料建词法索引、200题三条件排名、官方核分及两位Luna/max独立复核完成。用户请求试更好的BM25/分词，本轮不改[已冻结默认](../project/2026-09-20-default-freeze.md)。

## 结论

**本批没有找到可替换现方案的改法。** 只替换首轮词切分为Jieba搜索模式，纯BM25变差；只换Lucene式IDF，指标几乎不变。两种混合条件也没有超过原混合，仍低于同题纯向量。保留ICU＋SQLite BM25，不把库名、词切分示例或公式变化当作检索提升。

这不否定所有Jieba策略：本次刻意保留现有ASCII标识符扩展、中文双字补充与停用词。它只检验“在现有处理链中替换首轮分词”的接法，没有同时去掉重复扩展，也没有调用户词典。

## 具体改了什么

| 项目      | 固定或差异                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------- |
| A基线     | 现有ICU＋原SQLite FTS5 BM25                                                                       |
| B唯一变化 | 首轮word-pass改为jieba-wasm 2.4.0的cut_for_search，HMM=true，自带词典                             |
| B保持     | NFKC、小写、中文停用词、ASCII标识符整体/子词、中文双字补充、查询去重/最多128项/OR；无新增用户词典 |
| C唯一变化 | A的IDF从SQLite的clipped log(ratio)改为log(1+ratio)，ratio=(N−df+0.5)/(df+0.5)                     |
| C保持     | A词项、相同TF归一化、k1=1.2、b=0.75、精确文档词项长度；从全部匹配文档计分后取60                   |
| 混合      | BM25/dense=0.5/1，RRF10，两路候选最多60；向量阈值0.3                                              |
| 向量来源  | qwen3.7-text-embedding/1024的原冻结dense排名，不新增embedding/API                                 |
| 标题      | 官方片段标题字段为空，列权重仍2/1                                                                 |
| 查询/语料 | 原问题，不重写，不重切，不缩减完整干扰语料                                                        |
| 返回约束  | 官方排名评测，不施加产品每篇3或16000正文预算，不运行Agent/MCP/答案生成                            |

B和C未组合。C是IDF公式消融，不是完整Lucene引擎，不包括其norm量化等实现，也不是BM25L/BM25+对照。[SQLite公式](https://www.sqlite.org/fts5.html#the_bm25_function)、[Lucene IDF定义](https://lucene.apache.org/core/9_12_1/core/org/apache/lucene/search/similarities/BM25Similarity.html)

纯BM25输出的rrf_score为单路诊断值1/(10+rank)，原始词法分数另存bm25_score；0.5系数只用于hybrid融合。官方计分使用导出的唯一排名顺序，不把单路诊断值当作混合分数。

## 为什么没有明显收益

- B改变了141/200题的查询词项列表，全部200题的BM25前60顺序都发生变化；不是没有实际生效。整个语料词项总数从39037259降至38530019（−1.30%），但少一些词项并不等于检索更准。
- 原有多路扩展仍保留，Jieba搜索模式本身也带细粒度词；因此不能将这批结果外推成“独立的Jieba分词器都更差”。重复注入/双字扩展的消融仍未执行。
- 1562个不同ICU查询词项中1533个在库中匹配；匹配词项的中位文档频次181，最高41438/100001，没有查询词项触发SQLite的IDF下限。C改变了不少排名，但195/200题的BM25 nDCG不变；不能把“指标变化小”说成“所有排名都相同”。
- 查询词项最多44（ICU）和35（Jieba），本批未碰128项上限，因此不能把本次损失归于查询截断。
- 当前仍没有“哪一种分词词典更好”的通用结论。后续更有针对性的方向是分别消融同一原文位置的重复词项注入、中文双字补充，再考虑独立冻结的术语词典；不能直接对整篇文档去重词频，也不应根据本批qrels挑词。

[运行器](../../evals/run-lexical-pilot.mjs)先写冻结协议，在E盘新建contentless FTS索引；[辅助函数](../../evals/lib/lexical-pilot.mjs)只用于试验，没有改产品分词或依赖。固定Jieba版本的npm完整性与实际JS/WASM文件SHA均记录；安装使用ignore-scripts，查询阶段禁止fetch。

验证：

- 100001篇A词项逐篇与旧FTS正文相等；200题A的纯BM25/hybrid10顺序逐项复现，dense顺序保持。
- 200题手算SQLite公式与原生FTS5得分/顺序一致后，才接受C结果；没有只在原前60中重排来冒充全库新算法。
- [官方评分适配](../../evals/score-lexical-pilot.py)按qrels独立计算nDCG/Recall/Hit/MRR，重现三个原基线的逐题分数，再做配对统计。两位Luna/max分别核查公式/数据或隔离复跑，均无阻断。
- [隔离回归](../../tests/lexical-pilot.test.ts)覆盖原词项等价、真实重复词频保留、常见词IDF截断、空文档和SQLite原生评分等价。完整检查177通过、1既有跳过；Python评分输入6通过，默认CLI/MCP烟测通过。
- 本轮实际400次原生词法查询、200个手算控制、200个IDF变体排名；新增模型/API调用0。两个FTS索引及映射总文件约375MB；构建观察耗时98.71秒，非生产性能保证。计时中的C scoring-only不包含读取倒排项，不与原生查询耗时横比。
