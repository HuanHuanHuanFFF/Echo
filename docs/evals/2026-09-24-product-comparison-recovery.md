## 输入与实际证据

| 模块                                                        | 职责及验证边界                                                                                                                                                                                                                                                        |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [共同打包](../../evals/lib/product-evidence.mjs)            | 完整文档按冻结子问题顺序 round-robin 合并，按来源与正文去重；top10、每篇6、累计请求加响应20000 UTF-16字符，整块不足预算时跳过。另存选择轨迹，不把未发送的元数据计入证据。                                                                                             |
| [Dify 定位](../../evals/lib/dify-evidence.mjs)              | 只评分实际返回的 parent segment。重复正文必须经完整有序分区验证；重放固定版本的控制字符及特殊标记清理，只有实际进入空间分隔回退的长段才允许对应空格折叠。被删除的字符不计作已返回。                                                                                   |
| [Khoj 定位](../../evals/lib/khoj-evidence.mjs)              | 只评分 compiled 子片段，raw 父段用于校验来源。重放固定版本 Markdown 递归、标题尾部、Python 码点切片和 compiled-hash last-wins 规则，不把父段未返回内容算命中。                                                                                                        |
| [真实查询缓存](../../evals/lib/product-private-vectors.mjs) | 校验原捕获计划、每份真实请求/响应 SHA、模型维度、输入及向量绑定；267条私有查询核验通过，复用到实验网关，新增 API 调用为0。                                                                                                                                            |
| [评分前核验](../../evals/lib/product-run-integrity.mjs)     | 校验每个条件、范围、完整题量、源码、索引回执、结果 SHA 和原生请求/响应。固定单元重建原生排名；Khoj 同时核对真实请求的重排开关，防止条件混淆。所有所需范围核验通过并完成各范围评分输入与最终分母断言后，才统一写评分；不会因后一个库输入失败留下前一个库的分数半成品。 |

Dify 1.17.1 原生切块配置的字段虽叫 `max_tokens`，当前固定路径实际按 Python 字符计数，父段1024、子段512、overlap=0。不能把这个字段名当成相同 token 块大小。Khoj HTTP 原生返回最多10条，不报告它的 Recall@50。

FreshStack 固定语料按官方固定版本 loader 的 ID 字典采用 last-row-wins：LangChain 49514行对应49505个有效ID，Godot 25482行对应25477个有效ID；不是任意删除重复文本。固定单元保持原始文本和官方ID，不重切。

## 完整性、恢复与冻结

- [Dify 完整文档审计](../../evals/audit-product-dify-index.mjs)重新读取全部文档和父段，核对 ID、顺序、正文、状态与来源；[固定单元审计](../../evals/audit-product-dify-fixed.mjs)核对完整官方 ID 集合和正文；十万条收尾以只读 PostgreSQL 流式查询替代重复分页，保留原有相同的 position、正文、状态及身份断言，再检查 PostgreSQL 片段与 Weaviate 对象一一对应。
- [物理向量审计](../../evals/audit-product-dify-vectors.py)逐条核对1024维、有限值、单位长度、真实模型指纹及相同输入缓存向量，不能仅以“维度正确”代替模型正确。活动网关数据库先做一致性只读快照。
- [Khoj 审计](../../evals/audit-product-khoj-index.mjs)逐条核对原生 Entry、实际 compiled、来源映射和真实向量。固定单元以 corpus UUID 定位，同一文件允许多个官方单元。数据库导出使用逐行 base64 包装，避免正文控制字符破坏行边界；失败日志不打印正文。
- [Dify 写入意图](../../evals/lib/product-index-intent.mjs)在创建前保存 pending，成功后保存响应；网络结果不确定时停止并核对远端，不盲重试或复制文档。
- 2026-09-22 的 `index-freeze.json` 保留为导入参数冻结。恢复代码另记录修订指纹，不覆盖原冻结，不把 `index-inputs-frozen` 当作运行完成。
- [v2 索引回执](../../evals/lib/product-index-receipt.mjs)绑定全部来源审计、模型值审计和执行代码。正式全局查询冻结前加强校验时，先按 SHA 归档旧回执；正式冻结后禁止覆盖已有回执。查询与核分均验证该绑定。
- 查询前使用 `docker inspect` 仅读取容器 image ID，并与全局冻结逐项匹配；不读取容器环境。Khoj 实际部署源码另验证 `apply_filters` 在向量排序和截断之前，源码 SHA 与镜像一起绑定。
- Dify 额外核对原生 dataset 的模型/检索设置、实际已发布 workflow，以及不含密钥的模型 endpoint 配置快照。生成工作流或创建库时，未知写入结果需要先核对，不能靠重试猜测成功。

正式条件仍为 Echo A、Dify hybrid、Khoj dense、Khoj rerank，每条件3507个父题。完整文档共同预算适配和固定单元原生返回上限均在看结果前冻结。索引期间独立库曾并行导入以减少等待；资源竞争下的索引时间不作为产品速度排名。正式查询按条件串行执行，缓存延迟不冒充在线模型延迟。
