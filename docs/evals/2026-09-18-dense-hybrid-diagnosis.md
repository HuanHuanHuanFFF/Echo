# 最终集纯向量与混合：候选、排序和返回限制诊断

日期：2026-09-18。状态：同条件追踪、主线程验证及两位Luna/max独立复核完成，无未解决阻断。承接[最终200题结果](2026-09-18-final-four-arms.md)。本轮只分析原因，不改代码行为、参数、问题或标签，不执行新参数实验。

## 核心结论

本次差异主要发生在候选进入之后：BM25通过RRF改变同文片段先后顺序，“每篇最多3块”再把排序差异变成事实得失。11道题的12项不同事实，两组都已在候选并集中找到完整支持；混合补7项、丢5项，完整题4赢3输，所以净多1题、2项事实。

纯向量较容易把同主题背景排在具体事实之前；BM25能提升带精确字段/术语的证据，也会提升词面相近但回答另一问题的段落。不能把这次结果解释成“BM25全无用”或“向量没有找到答案”。

- 400条原始主集结果只读计分；21道至少一组不完整的题全部追踪，另取4个MRR变化代表，共25个父题、50条同条件诊断重建。
- 用原真实查询向量、原索引、原请求和冻结b454686运行时；原packResults与附加事件记录的副本均逐项等于原响应。只在内存副本添加追踪，不修改运行时文件。
- 用只读SQL补查全库dense/BM25名次，不把它们当作扩大候选量的新实验；决策归因使用实际60候选及真实打包事件。
- 50份响应完全匹配、源码/语料/配置/数据库哈希核对，网络/API为0，没有新模型费用或新参数条件，不增加最终题数。

## 1. 纯向量为什么丢这部分证据

向量名次表达语义接近程度，不保证同文排在前面的三块恰好包含全部必要事实。每篇3是整个父题共享，多个子问轮询时也会竞争这三个名额。

| 案例                        | 正确片段在dense的位置 | 混合的位置  | 实际原因                                                                                                |
| --------------------------- | --------------------- | ----------- | ------------------------------------------------------------------------------------------------------- |
| B-T15：grades格式不一致     | dense4，BM25 1        | 融合2       | dense先选了同文提示代码、学生描述、场景介绍三块，解释格式不统一的块被单篇上限挡住；混合让解释块先占名额 |
| a-test-038：半成功状态处理  | s2 dense3，BM25 1     | s2融合2     | 多子问共享同篇名额；dense轮到目标时该文已3块，混合提前选中                                              |
| B-T16：函数结果与原调用对应 | part-2 dense3，BM25 1 | part-2融合1 | 对应调用结果的关键代码先进入，dense下被同篇前三块排除                                                   |
| M-T53：从少到多提示         | dense11，BM25 2       | 融合3       | 答案仍在60候选内，dense访问它时同篇名额已满；混合提升后保留                                             |
| M-T55：固定示例与微调       | dense8，BM25 5        | 融合4       | 目标片段在全局第4块入选，但该来源此前不足3块；dense下单篇名额先满                                       |

这些收益都属于重排已有候选，并非BM25从60名以外额外找到缺失事实。D-T28则涉及一个事实跨两块：两组都返回29–55行，混合还选中57–60行的边界说明；纯向量的第三个同文名额给了其他限制段落，拼不齐冻结范围。

## 2. 混合为什么也会退化

当前RRF对一个候选计分为1/(10+dense名次)+0.5/(10+BM25名次)，某路未入选时不加该项。它融合名次，不直接使用余弦差距，也不知道片段是否完整回答某一事实。

| 案例                              | 目标dense→融合名次 | 最终发生什么                                                                                         |
| --------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------- |
| D-T27：浏览器请求流向Python再返回 | s1第1→第3          | 请求流程原本第1；设计说明、演示端点被词面加分提升，另一个子问又选入iframe解释；轮到流程块时同文已3块 |
| D-T29：词频怎样映射字号           | 第2→第5            | BM25优先Options/Features/Usage；三块均来自同文，Implementation Details中的对数字号缩放被挡住         |
| M-T54：提示线索                   | 第2→第5            | 目标在BM25全库第86，未进该路60候选；基础提示、示例等同主题段落排到前面，占满同文三块                 |
| M-T14：CSP属性跨浏览器边界        | s2第1→第2          | 两子问轮询；只下降一位，前面已合计选满该文3块，仍会丢证据                                            |

D-T29是清楚的数值例子：目标dense2/BM25 13，RRF约0.10507；Usage虽仅dense5，但BM25 1，得分约0.11212，排到目标前。词面排名可以压过语义排名，即使BM25权重只有0.5。

这几题不一定去了完全无关文档：多数仍命中了正确笔记，却选了其中不够回答问题的三块。调低BM25也不是单向收益，前节被它救回的事实同样可能后退。

## 3. 全部缺失事实在哪一层被挡住

统计每个缺失事实对应的未返回原文行，找到包含这些行的候选，并记录首个关键候选排除事件。一个事实跨块时可能已有部分正文返回；按“事实×模式”计数，不是不同题数，也不是保证能修复的数量。

| 当前条件 | 缺失事实 | 索引无完整支持 | 候选并集无完整支持 | 先被每篇3挡住 | 先被topk10挡住 | 首次因预算挡住 |
| -------- | -------: | -------------: | -----------------: | ------------: | -------------: | -------------: |
| 纯向量   |       25 |              0 |                  0 |            20 |              5 |              0 |
| 混合     |       23 |              0 |                  0 |            16 |              7 |              0 |

两组各有1项topk排除同时已满单篇名额（M-T22）；实现先检查topk再检查每篇数量，不能从首个原因推断只有一个约束。

因此，当前候选60与0.3阈值并未使这些缺失事实消失在候选阶段。两组各有58道题发生过预算排除，但本次缺失事实的首个关键排除不是预算；“58题有预算排除”不等于“58题因预算丢答案”。预算也可能影响此前已选集合，不能宣称没有间接作用。仍未做放宽上限的反事实实验，不能据此保证每篇4或更大预算能恢复全部事实。

## 4. 两组共同失败：子问和块形状也有影响

共有14道题两组都不完整。大多数仍是正确文档内的名额竞争；另外M-T23的4项原冻结锚点两组均未覆盖，目标块在两子问的dense排名均为8，混合为9/10，轮到它时全局已10块。

该题父问句限定Cloudflare Workers和JavaScript页面计数器，但冻结子问只保留“报告怎样设置本地启动与数据库绑定”“报告怎样执行SQL、状态在哪里”等泛化表述，产品名没有进入实际查询。前列因而出现Pyodide/Datasette和Agent State等主题相近内容。Echo接收的是这些子问，并不会自行拿父问题补回上下文。

同时存在标签边界：两组已经返回该文13–31行，包含与F1原43行等价的wrangler本地启动/持久化命令，只是这一替代示例未列入原标签。因此0/4不能说成四项内容全都没有返回；F2/F3/F4的绑定配置、SQL接口、实际状态路径仍不在返回正文中。本轮保持最终标签和分数不变，未发布选择性补分。

这是输入丢定位信息和现有排序偏差同时存在的证据；本轮未改写子问做对照，不能报出“补上名称能提升多少”。它不否定开发集上拆分总体有益，只表明每个子问也应保留足够定位信息。M-T12的第二子问同样缺少SQLite/WAL限定，仅问部署限制，出现跨主题候选。

D-T14还显示切块与严格标签的相互作用：两组都返回24–52行，已有OAuth成功但MCP未实现规则工具的核心说明；冻结F1范围50–54还要求后续API-token句，而54行单独成块。混合给它一个名额，于是拼齐F1，却挤掉118–132行的规则API路径F2；纯向量保留API路径，却拼不齐F1。

所以该题1/2对1/2不是同一事实，也不能解释成某组完全没理解OAuth边界。原标签保持不变，此处仅揭示严格原文范围覆盖与语义可答性之间的边界；不是自动认定标签错误。

## 5. 为什么纯向量MRR略高

196道可答题中，混合的首个单块有效证据排名在13题改善、17题退化、166题相同；倒数名次差合计−1.60952，除以196后为−0.00821，正好对应0.85349对0.86170。

MRR衡量第一块有效证据有多早出现，完整覆盖要求最后缺失的事实也补齐。混合可以把少数题的后续必要片段挤进结果，净多1道完整题，同时让另一些题第一块有效证据稍后出现；两项指标并不矛盾。
