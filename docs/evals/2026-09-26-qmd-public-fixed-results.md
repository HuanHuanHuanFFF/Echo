# QMD 公共固定单元全量对照（2026-09-26）

## 结论

- 在固定的 302 道 FreshStack 查询上，QMD 默认本地重排相对 QMD 无重排，两组的所有指标点估计都更高。Godot 的 6 项配对 bootstrap 区间均高于 0；LangChain 的 nDCG@10、Coverage@20、Recall@10、Recall@50 区间高于 0，α-nDCG@10 和 MRR@10 区间包含 0。
- QMD 默认重排在两组测试的所有对比指标上都低于 Echo 当前公开基线；逐题配对 95% bootstrap 区间均低于 0。这是固定公开测试集上的系统级比较，不能单独归因于检索算法，因为 embedding 模型与管线不同。
- LangChain 默认重排 203 题中有 3 题因本地 reranker 输入超过默认 4,096-token 上下文而失败（1.48%）；这 3 题仍留在分母中并按零结果计分。无重排版和 Godot 默认版没有查询错误。

- 本轮只测单次检索排名，不运行答案生成、多轮 Agent 上下文或补读。
- 汇总指标使用 FreshStack 官方评分实现及 pytrec；置信区间使用 10,000 次逐题 paired bootstrap，seed `20260926`。配对差定义为“左侧减右侧”，正数有利于左侧。

## 失败题与评分口径

LangChain 默认重排的 3 个失败题都包含很长的问题正文，长度分别为 12,090、13,518、13,253 字符；QMD 错误信息报告的 rerank 输入至少需要 5,495、6,217、4,807 tokens。QMD 安装包实现的默认 `QMD_RERANK_CONTEXT_SIZE` 为 4,096；变量未设置。失败题 ID、标题和错误全文见机器可读汇总。无重排版能够处理这些题。

第一次 LangChain 默认重排尝试使用 60 秒 MCP 超时，只留下 19 条，已保存在 E 盘 attempts 目录且未计分；主运行从头按冻结的 600 秒请求超时重跑，203 题完整收据通过。
FreshStack 官方 alpha-nDCG helper 对空排名会抛 `KeyError`。本地评分脚本只把非空排名传给该 helper；官方 helper 仍以全部标注题数为分母，故失败题贡献 0 而没有从平均值中移除。其余指标也保留完整 203 题分母。未重跑失败题、未提高上下文后混入主结果。

## 解释边界与后续

- 这两套语料是技术问答和代码支持，不是个人笔记、日记或学习记录；本结果不能证明 QMD 或 Echo 在个人知识库上的通用优劣。
- 同一查询、官方 ID 和标注使排名指标可逐题比较，但 Echo 使用不同 embedding 模型与检索流程；比较的是端到端系统表现，不是单独比较 reranker 或某个算法。
- QMD 本地重排显著改善 Godot；在 LangChain 上，前四项中的 α-nDCG@10 与 MRR@10 区间跨 0。QMD 与 Echo 的差距在两个数据集和六项指标上均为负，且逐题 bootstrap 区间未跨 0。
- 一个可验证的后续方向是单独提高 `QMD_RERANK_CONTEXT_SIZE`，复测这 3 道超长题；若要修改主评测结果，必须用统一新上下文配置重跑同一数据集，当前数字保持为 QMD 2.8.3 默认 4,096-token 条件。
- 没有把本地模型/索引、个人笔记、原始排名或逐题文本提交到仓库。外部原始运行、freeze、receipt、完整索引与审计收据保存在上述 E 盘隔离目录。
