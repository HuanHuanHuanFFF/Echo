日期：2026-09-22。状态：**用户已确认方案；部署与接口预检进行中，尚未运行正式比较。**

本轮承接[cap6 全量结果](2026-09-22-cap6-public-full-results.md)，比较现成产品的原生导入、切块、索引及检索。它不替代历史评测，不调整 Echo 产品默认。较新的本记录仅确定外部产品对照范围；旧结果和已开卷边界保持。

## 范围与条件

- Echo 主条件采用已测 A：新综合 1.0.1、MiniSearch 无匹配词数量乘数、BM25/dense=0.5/1、RRF10、候选60/60、topk10、每篇6、累计预算20000 UTF-16字符。原 B 仅为历史参考，不增加参数网格。
- Dify：固定稳定版本，使用原生段落型父子切块、高质量索引和加权混合检索。部署前核对具体向量后端和插件的实际行为。
- Khoj：固定稳定版本，使用原生 Markdown 导入与 search 路径；原生重排前、后的结果分列，记录实际模型及成本。不把带重排的成绩解释为仅切块收益。
- 主比较统一使用 qwen3.7-text-embedding、1024维和既有 DashScope endpoint；依实际发送文本核对维度、长度处理、前缀及缓存。产品兼容性不由文档声明代替真实调用验证。
- 不调用 Agent 生成答案、多轮改写或联网搜索。私有题保留冻结子问题，所有方案接收相同查询并共享同一父题累计预算。

配置、版本、模型输入、原文映射和预算适配通过隔离样本后，写入机器可读 freeze，再开始正式全量。预检不得用题目标准答案选择切块或检索参数。

## 公平比较与评分

1. 完整保留各产品原始返回和原生配置；预算适配层的处理单独记录，不冒充产品默认。
2. 全文任务采用统一 top10 和20000字符累计预算，明确来源上限与子问题合并规则。各产品分数尺度不同，不直接混加分数或照搬相似度阈值。具体适配算法在看成绩前冻结。
3. 评分依据原文证据，不依据 Echo chunk ID。导入文本不包含 `echo_id` 或标签；保存清洗前后映射。找不到可靠映射时记为映射失败，不能猜测命中。
4. 个人题报告完整证据、事实覆盖、Hit/MRR、无答案返回、实际预算；QASPER同时报告完整覆盖与官方F1。FreshStack沿用官方alpha-nDCG/Coverage/Recall，Du沿用nDCG/Recall，分库报告。
5. 分别记录新embedding/API、缓存命中、索引耗时/体积、CPU/内存、原生查询及重排延迟。缓存运行时间不冒充在线API延迟；部署资源差异与检索质量分开。
6. 运行结束核对完整题量、语料/查询/源码/配置指纹，并做逐题配对分析。结果不自动触发换默认。
